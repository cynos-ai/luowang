# 自适应 Thinking 与 OSS 配置体验 Intent

- 日期：2026-10-04
- 状态：已确认实施
- [Spec](spec.md) · [Plan](plan.md)

## 问题

运行阶段把 `off`、`low` 当成模型必须原样支持的字面档位。模型虽然提供足够的推理档位，仍可能因为命名不同而无法运行。对象存储页面同时平铺必填项和高级选项，URL 少写协议时只显示“能力尚未提供”，凭据输入还用重复的解释性标签占据空间。

## 期望结果

- 运行阶段先读取模型实际支持的 Thinking 档位，再按阶段所需的相对强度选择可用档位。
- OSS 页面先展示建立连接所需的配置和凭据，再展示选填项。
- 常见 URL 漏写协议时自动使用 HTTPS，并通过就地帮助给出格式示例。
- Secret 保持不回显，但凭据输入不重复显示“新值（不会回显）”。

## 约束

- Thinking 选择只能使用 Provider 模型元数据，不能猜测或通过模型文本回答决定。
- 不改变 Main/Runner/Reviewer 的 Session 数量、职责或模型选择。
- OSS Secret 继续保存在加密 Secret Store，不进入普通配置、日志或页面正文。
- 保留现有 S3 兼容配置能力，不绑定单一云厂商。

## 非目标

- 不自动替换操作者选择的模型。
- 不探测或保存 Secret 原值。
- 不修改项目级凭据页面或对象存储数据布局。
