## 1 范围与规则归属

本变更以完成审查集成的 [项目并行](../luowang-project-concurrency/spec.md) 为基础。延续 [单向交接](../luowang-single-handoff/spec.md)、[语义判断](../luowang-model-semantic-decisions/spec.md)、[期望完整性](../luowang-expectation-integrity/spec.md)、[证据完整性](../luowang-evidence-completeness/spec.md)、[复测证据读取](../luowang-retest-followup/spec.md) 和 [按 Run 清理](../luowang-run-scoped-cleanup/spec.md) 的边界。

新增主动停止是本 Spec 的明确扩展：运行中请求可以因管理员操作中断，不能冒充正常四 Session 完整执行。正常完成和初始化的既有 Session 分流保持。停止后的重启协调仅处理停止意图与所属资源，不扩成跨进程自动业务数据清理系统。

## 2 执行前准备

### 2.1 项目条件与本次计划分开

项目 readiness 继续检查仓库、部署、环境、镜像和凭据；显示检查时间、对应配置版本以及需重检状态。配置有值、检查曾通过、当前可用必须区分。共享依赖检查复用原 owner，不在每次轮询或点击时重新发送付费模型探测。

Main 在现有规划 Session 中取得当前工具与资源能力事实，并在 plan.md 中说明选定场景的必要观察、验证路径及已知缺口。复用现有资源和 write_plan，不新建长期能力 catalog、场景字段或第五个角色。Harness 不从计划文字中用正则推断浏览器、数据库或业务需要。

只展示实际存在的能力及核验状态，例如浏览器、受控 HTTP、受控命令、已配置的非生产观察入口。清理接口支持账号删除不能推导为支持密码存储查询；源码存在散列调用不能替代运行时存储证据。未知条件明确为未知，不由 Agent 自报升级成可用。

### 2.2 已知缺口的处理

已选且适用的期望不能因工具缺失而被删除、降级或改写为不适用。Main 明确缺口；Runner 不反复调用已明确不可用的能力，并在执行记录中说明受影响验证。其他独立、可验证的场景可继续；Reviewer 保留逐场景结果和已确认产品失败。

如果整批没有可执行的业务验证，仍按现有角色交接给出诚实的 blocked，避免无意义的业务操作；不伪造验证、删除执行清单或新增跳过审核的通过路径。客观协议、权限和能力故障沿用现有提前失败边界。

Runner 在结束所属 Session 前核对原计划中的必要验证是否已有实际观察；有能力补做且尚在本 Session 时完成遗漏，缺资源则记录不足。Reviewer 继续独立审核，不回调 Runner 或启动自动返工循环。典型反例包括“页面退出登录”不足以证明旧 Cookie 在服务端失效。

## 3 安全停止与取消排队

### 3.1 用户动作与结果

新增项目范围内的“取消排队”和“停止本次测试”。操作展示项目、queueId、存在时的 Run ID 与影响，重复请求幂等；API 校验认证、同源写入及项目归属。停止一个请求不隐含暂停项目、取消其他请求或停止另一项目；页面明确后续队列仍可能继续。

| 当前阶段                 | 目标行为                                                          |
| ------------------------ | ----------------------------------------------------------------- |
| queued 尚未认领          | 原子取消，终止该请求，不建立假 Run，不调用模型                    |
| 已认领且尚无 Run         | 持久化停止意图，在可安全退出的准备边界停止；不再启动 Run          |
| 规划或执行或审核或汇总   | 请求中止当前 Session/所属操作，不启动下一个 Session；保留实际产物 |
| Harness 收尾中           | 记录请求并显示收尾进度，不因重复点击跳过必需清理或覆写结论        |
| waiting_archive 或已完成 | 明确已结束执行，停止不取消归档；继续原归档流程                    |
| 已被管理员停止           | 返回同一停止事实，不再次清理、不重复释放资源                      |

复用 `interrupted` 表达未完整完成的 Run，`result=null`；以明确的持久化原因区分 `user_requested` 与进程异常。queued 取消只留下请求终态和原因。运行结果 `passed/failed/blocked` 不增加 cancelled 值，不为终止制造正式模型结论。

停止请求与完成竞争以持久化终态为准：完整完成事实先成立则保留结果，返回已完成；停止先生效则不得事后改为完整完成或推进。停止中的临时进度可以展示，但不另外维护一套独立 Run 状态机。

### 3.2 中止与资源回收

停止意图按实例、项目、queueId 和已有 Run ID 绑定，覆盖 resolveTarget 和 Session 创建之前的窗口；不能只给 activeRuns 中已开始的 Run 加按钮。

向当前 SDK Session、受控命令/HTTP 和所属 MCP 子进程传播中止，校验实际 SDK 的中止能力。`dispose()`、Promise 超时返回和停止底层请求不是同一事实。停止后禁止新工具操作，但不能撤回已经到达目标应用的请求或已经完成的 Git 写入。

合作退出的初始等待上限为 30 秒，之后仅对确认属于该任务的本地执行资源执行有界终止；每个外部关闭/核对操作均设超时，并记录未完成项。30 秒是开始升级终止的期限，不是所有远端副作用消失的承诺。具体 adapter 超时沿用已有值，确需调整需有测试依据。

Git push 等结果不确定时先核对原 prepared/resolved/internal ref 与远端，不自动重建提交、回退分支或开始新 Run。不用实现停止的机会引入 #104 自动重试。

确认执行资源退出后，Harness 尝试本 Run 既有收尾，保存成功、失败或未知事实。业务数据删除仍只能由现有 adapter 处理；不让 Agent 接触清理 Token。无完整 report 时在运行记录中保留清理告警，不制造正式 report/review。

资源退出及有界收尾结束前保留项目互斥和实际占用；无法确认仍在执行的资源时保留占用与告警，不通过删活动项释放假名额。其他项目的已运行任务继续。已证实计算资源结束但业务清理失败可结束占用，保留数据残留警告，不谎称环境已恢复。

重启先恢复停止标记，再协调资源；停止过的准备请求不得被原有 requeue 路径重新执行。保留已有 interrupted 恢复，不自动续跑模型或声称断电期间完成了清理。

## 4 诊断与下一步操作

### 4.1 分开显示事实

Run 摘要和工作台分开显示：测试结论、运行生命周期、缺少的验证、归档状态、清理状态。准备失败尚无 Run 时提供请求详情，不把无报告说成测试失败。

每项可处理问题展示受影响项目/请求/Run、首次及最近观察时间、来源、简明原因、可执行下一步。来源至少区分程序客观故障、Reviewer 声明的验证缺口、管理员停止、历史未知。模型文字保留来源，不用关键词把普通叙述升级成网络/权限/产品故障。

问题入口是现有 queue/run/archive/activity 的读模型，不建立需要另行维护状态的工单系统。旧记录没有机器原因时显示原文与未知分类，不自动猜测。已解决的依赖状态不能清除旧 Run 的 blocked；新检查或新 Run 以关联记录说明后续结果。

### 4.2 操作语义

| 操作             | 范围与约束                                                                                |
| ---------------- | ----------------------------------------------------------------------------------------- |
| 重新检查条件     | 调用现有项目或系统检查；不启动 Run，不承诺检查成功即测试通过                              |
| 前往配置         | 定位对应项目/全局设置；遵守正在运行时的配置保护                                           |
| 重试归档         | 复用原 Run 的 Archiver 和固定工件，只处理已有失败/partial；与后台重试互斥幂等，不调用模型 |
| 重新测试当前版本 | 创建新请求和新 Run，关联来源 Run；沿用现有认领时冻结 HEAD 的规则                          |
| 查看清理问题     | 展示原 Run 的真实回执、剩余或未知状态以及既有处理说明；不增加任意删除入口                 |

重测确认展示“认领时固定当前场景分支提交”，不能承诺原提交复测。创建后展示新旧 target 是否相同、是否未知以及配置是否变化；请求幂等令牌避免双击产生两次模型 Run。原历史报告不变，不复制旧证据作为本次验证。

本阶段不开放任意旧 SHA 的正式运行，也不回放原 merge-source 写入。无来源 Run 的准备失败可带原请求的脱敏上下文引导新请求，但有 Git 写入影响时必须显示范围并沿用原确认规则。

## 5 阶段耗时与模型用量

工作台与 Run 页显示实际阶段、阶段开始时间、阶段耗时、最近活动及数据刷新时间。区分仍在等待模型/工具、长时间没有新活动、页面轮询失败；没有心跳不是已经挂死，不据此自动停止、标失败或重跑。

提供最后活动距今时长和固定说明，不新增虚构完成百分比、预计完成时间或无依据的全自动卡死判断。日志和诊断只公开受控类型、错误码和脱敏摘要，不开放原始 Provider 响应、任意日志下载或进程环境。

复用现有 `agent-usage.json` 和 SDK usage，按 Run/角色展示输入、输出、cache read/write、总量、已结束 Session 数，以及 SDK 估价。当前 SDK 尚未提供完整实时值时显示“已结算 Session 的部分用量”，不把缺失显示为零。保持去重及重启后读取一致；估价不是 Provider 账单，不添加金额停止策略。

只增加现有控制台的必要信息，不搭建独立监控平台、外部通知或全局成本结算系统。

## 6 模型回归与验收归属

### 6.1 本轮效果矩阵

在实现前固定输入、预期判据与基线版本，在实现后固定候选、角色资源、模型/Thinking、配置和实际调用。使用生产 Session 与工具读取路径；冻结工件回放、真实执行和工程模拟分别标注。

必须有以下六类案例，每类包含有能力/缺能力或错误/正确对照：存储观察不足、旧 Cookie 重放遗漏、环境不可用、已知功能失败与证据缺口并存、充分证据不误阻塞、清理失败不改功能结果。不能只重跑此前失败项而省略正确对照。

每类固定两个正反子例，首轮每个子例在基线与候选各执行 3 次，共 6 × 2 × 2 × 3 = 72 个案例运行；案例可能包含多个 Session，另记实际 Session/模型请求数。涉及业务动作的案例使用各自独立数据和完整 Run；只验证 Reviewer/最终 Main 的案例用固定工件回放，不冒充完整现场执行。前置条件改变的测试必须单列，不能把新提供的观察资源带来的通过归因于模型改进。

冻结判据包括：必要验证是否保留、已知不可执行操作次数、必要证据漏采、无依据通过、无依据失败、正例误阻塞、清理与功能结果是否混淆。完整记录成功、失败、耗时和用量。候选必须在存储缺口和旧 Cookie 两类核心案例的每个子例达到 3/3 符合预期，且全部正反对照不出现无依据通过或错误归因，才可声称本轮专项有效；改善结论附逐例计数和样本局限，不承诺普遍成功率。

工程自动检查、AI 按固定判据的复核与真实人工评分分开。没有人工评分时 `humanScoring=not_run`，不能由 AI 填成通过。

### 6.2 既有质量欠账与证据选择

#95 对应的历史场景设计对比另有八类规划输入、至少四组 Reviewer 工件和两版本各三次的完整矩阵。本阶段先核对并运行这组适用的完整矩阵，保持其独立 AC 与评分要求；需要更新的旧草稿交接必须按当前 single-handoff 对齐，不恢复 draft-report。与六类专项的同一案例只有输入、判据和调用条件完全相同才可共用实际记录。

专项通过不能自动关闭 #95；未执行项、未达到的模型指标和缺少的人工评分如实保留。模型效果不满足时保留失败并修正受影响部分，不能通过改变期望或筛掉失败“完成 Plan”。

本轮验收显式绑定候选 commit/image、角色资源哈希、模型、实例、项目、queue、Run、target、配置指纹和检查器版本；字段不得含 Secret。检查器拒绝错批次、错项目、错版本、证据缺失及完整性错误。延续已有 live manifest/contracts，不实现 #103 的通用跨候选复用；每种证明仅支持实际覆盖的 AC。

## 7 兼容与数据保护

停止意图、原因、来源 Run 关联及必要用量摘要优先扩展现有 queue/recovery/store；实现前列出字段、归属与迁移。不引入第二套运行事实库，不靠内存独自保证取消幂等。新字段对历史记录采用 unknown/null，不回填虚假原因或零用量。

对历史隔离副本验证升级、读取和备份恢复；若 schema 不能供旧程序直接使用，回退必须停机恢复匹配备份，不能宣称直接降级可逆。保留所有历史报告、归属、证据和 Secret 加密配套关系。
