## 问题

罗网已经能管理多个项目，项目并行的开发与验收见 [项目并行 Plan](../luowang-project-concurrency/plan.md)。2026-10-03 核对时 PR #120 仍开放，最终提交 `8861421629736d0c6d61b9b65d4cc1a48f1708ca` 的 CI 通过，尚未完成审查集成，不能把它当成已发布能力。

这轮实际运行暴露了两个不同的问题：A1/A2 缺少验证密码存储的运行时观察资源，A3 漏做删除账号后的旧 Cookie 服务端重放。前者需要提前识别资源缺口，后者需要改善规划与执行。审核阻塞是合理结果，不能靠降低期望、重写报告或不断重试把它们变成 passed。另一次应用停机是预定故障，与模型漏测分别统计。

日常使用还缺少贯穿运行前、运行中和运行后的处理流程。管理员可以看见项目状态、活动、报告和清理告警，但尚不能安全停止单个请求；遇到长时间运行或 blocked 时，仍需自行判断是缺资源、漏验证、执行异常，还是仅归档未完成。现有用量记录未直接成为 Run 页的可用信息。

## 期望结果

- 开跑前明确本次验证需要什么、哪些已检查、哪些仍未知，减少已知缺资源情况下的无效操作。
- 运行中能理解正在等待什么，必要时停止指定任务，其他项目继续运行。
- 运行后清楚区分功能结论、运行异常、证据缺口、清理告警和归档问题，并找到适用的下一步操作。
- 重测、重检依赖和重试归档各有清晰含义，不重复付费执行、不修改历史事实。
- 能看到阶段耗时、已取得的模型用量与估价，理解等待和成本，而非依赖终端人工排查。
- 通过固定输入和正反例判断模型是否少漏测、少误报；保留失败和未验证项。
- 前一阶段代码完成审查集成，新阶段拆成可独立验证和回退的小批次交付。

## 范围

本阶段形成一套连贯的运行管理改进，包括：PR #120 审查集成、执行前准备、单任务停止、诊断与后续操作、运行耗时与用量、固定模型回归及整体验收。优先级是减少人工排障，再提高测试有效性；不按 issue 数量堆叠功能。

## 约束

保留同项目串行、跨项目有界并行，正常 Run 四个隔离 Session、三组角色配置、固定 target/image、受控 Secret、角色工具隔离、场景 patch allowlist 和报告自动归档。语义判断仍由角色负责，Harness 核验客观能力、结构、安全和完整性。

管理员停止必须保留已经发生的操作与副作用事实。无法证实进程、容器或数据已经清理时，不能用“已停止”冒充一切恢复正常。历史报告和已有产品失败不因停止、重测或清理问题而改判。

模型费用继续由用户外部额度控制，不擅自增加本地调用次数或金额限制；评测采用预先冻结的矩阵，避免以反复采样挑选通过结果。版本号、正式发布和长期实例升级仍需独立授权。

## 非目标

- Git 代理和传输自动重试（#93/#104），以及对网络故障根因的无证据归因。
- 通用工作流引擎、暂停后续跑模型 Session、模型自动循环修复或自动重跑 blocked。
- 新租户、分布式 worker、同项目并发、跨环境矩阵、自动部署被测产品。
- 任意数据库/SQL 访问、任意探测地址、扩大浏览器代码执行权限。
- 把跨候选历史证据直接计为新候选通过，或以模型评分增加产品报告发布门禁。
- 自动删除历史报告、数据卷、镜像和 OSS 对象；外部通知与第三方监控平台接入。

## 后续决策

本轮按 Spec 给出的保守边界安排实施，不需要先决定新版本号。若验证证明 SDK 无法可靠中止、需要改变正式结果语义或扩大目标数据访问权限，应带具体替代方案向负责人逐项确认；不能以实现方便为由悄悄扩大范围。
