# 单向角色交接与独立收尾 Spec

状态：已实现并通过工程验收；有界真实模型复测已完成，整体质量仍未通过，见 plan.md。

## 优先级

本变更覆盖默认布局、MVP、v0.7 及场景设计质量 Spec 中关于草稿、最终 Main 输入和收尾清理的旧条款；其他安全、审批、固定版本和发布规则不变。无需旧格式兼容，不改写既有评估记录。

## 单向交接

1. Main Planning 写 plan.md，必要时写受限场景 patch。
2. Runner 只写 execution.md，记录实际操作、观察、偏差和真实证据引用，登记临时数据；不生成 draft-report.md，不负责最终收尾声明。
3. Reviewer 读取计划、运行记录、存在的 patch 和相关原始证据，独立形成 review.md。审核报告完整交付按计划的逐场景结果、已确认 Bug、依据与稳定证据引用、覆盖缺口和不确定性，而不是仅同意 Runner。保持原始图片/命令读取的既有权限边界。
4. 最终 Main 只读取 plan.md、review.md（初始化仍允许受限 patch），据审核结果整理正式报告并受限查询 Issue 候选；不得读取 execution.md、原始证据或草稿重复审核。查询前置改为已读 plan/review。报告 frontmatter、场景选择清单和结果聚合不变。
5. 初始化候选 Main 从 plan/execution 接收侦察，无草稿依赖；四/六/三 Session 分流不变。
6. 删除草稿 writer、工件类型、归档/索引允许项和依赖测试。正常本地四份 Markdown，目标仓库正式报告仅 review.md/report.md；特殊场景审核仍只保留 patch/report。不存在兼容分支。

## Harness 收尾

- 上传测试证据仍在 Reviewer 前完成，供真实审核；统一测试数据清理在最终 Main 结束后、Run 完成和归档前执行，不创建新模型 Session。特殊审批和可捕获异常也执行收尾。强制杀进程、断电不能保证执行 finally；重启仍标记 interrupted，不自动声称已清理，也不引入新的跨进程清理恢复系统。
- 只有受控清理 adapter 的真实删除及独立查询能确认清理，Agent 不再提交/确认收尾清理声明。无数据无需虚假 adapter；无 adapter、失败或查询不确定均明确留下未完成信息。
- 获取 Run 标记和登记数据的工具必须按 manager 的实际能力说明清理适配器已配置、未配置或尚未确认；已配置不等于清理成功。默认未配置时，创建前可见的工具描述及登记回执不得承诺自动删除。未知自定义 manager 不推断为可用，不新增删除工具、权限或影响测试结果的门禁。
- Harness 在报告末尾写自身拥有的清理收尾区，记录脱敏状态、残留标识和必要原因；模型不能伪造该区。异常无报告时保留在运行记录/活动中，不制造可信最终报告。
- 清理失败不加入测试 blockingReasons，不改变 passed/failed/blocked、逐场景结果和已确认 Bug。场景本身验证删除行为时，实际删除失败仍由 Reviewer 判产品失败。后续若确知残留影响测试前置，应如实判受影响验证条件不足，不静默复用受污染环境；不新增自动跨 Run 风险分类系统。
- 保留证据不可用等原有测试阻塞规则。收尾告警不等于通过正式发布验收。
- 证据工具描述以实际配置能力为准；本地评估替代传输须明确告知模型，不以未告知的替代惩罚模型。

## 验收

- 真正的角色工具隔离：Runner 无草稿 writer；最终 Main 无执行/草稿读取；Reviewer 无收尾确认工具。
- 四/六/三 Session、初始化候选交接、特殊两工件及最终 patch 未重跑仍 blocked。
- 正常和异常路径均调用收尾，成功/无 adapter/部分失败/异常可见，失败不改 passed 或 failed，不丢失 Bug；残留与凭据脱敏。
- 归档和索引只接受新工件集合；本地生产 Pi 协议、边界测试及完整工程验收更新，不冒充真实模型或官网验收。
