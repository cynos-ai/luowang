# 单向角色交接与独立收尾 Intent

## 问题

后续生产路径核查发现：默认未接入清理 adapter 时，工具描述仍承诺 Harness 会统一清理，容易让 Runner 在没有自动清理能力时误判数据处置条件。期望在创建前及登记后如实告知能力，而不是扩大删除权限或用告警改写功能结论。

Runner 同时写运行记录和报告草稿，最终 Main 又读执行、草稿和审核，造成职责重复、新旧说法混杂。清理状态在不同阶段重复转述，收尾失败还会覆盖已经成立的测试结论。评估中本地证据传输沿用 OSS 工具说明，也造成信息来源误导。

## 期望

每个角色只交付自己负责的结果；审核依据真实捕获的证据，最终汇总不重复审核。收尾集中处理，清理失败明确提醒，但不改写已完成的功能验证结论。删除重复草稿，不保留旧格式兼容。

## 影响与约束

影响角色工具、工件、初始化、归档和本地验收。保留三组配置、正常四个隔离 Session、固定 target、Secret/路径/证据捕获边界。删除功能本身失败仍是产品失败；测试后清除临时数据失败是运维收尾问题。无生产或共享账号操作、无远程发布，不迁移或改写旧评估事实。

## 非目标

不增加角色、状态机、数据库事实源或通用清理脚本权限；不整体重写场景设计指令，不承诺模型质量已通过。
