# 全局设置凭据归位 Plan

- 日期：2026-10-04
- 状态：已完成
- [Intent](intent.md) · [Spec](spec.md)

## 1 修改范围

1. 调整全局设置路由和导航，删除独立凭据分组并规范化旧地址。
2. 补全模型页面的 Provider API Key 清除能力。
3. 将 OSS Access Key ID/Secret 编辑器放入对象存储页面，保留凭据独立轮换。
4. 更新路由、UI workflow、导航和响应式检查，不改变项目凭据测试。

## 2 风险与控制

- 凭据入口移动但数据不能移动：继续调用同一部署 Secret API，以原 metadata 展示状态。
- 全局执行锁可能误伤归档恢复：OSS 普通配置继续锁定，凭据按钮单独按 busy 状态控制。
- Provider 普通配置保存成功而 Secret 保存失败：显示部分成功消息并重新加载服务端事实。
- 旧书签失效：旧 URL 使用 replace 规范化为模型设置。

## 3 完成证明

- 路由测试覆盖旧全局地址规范化和项目凭据地址保留；UI workflow 覆盖四个入口、设置/轮换/清除、不回显，以及 Provider 与 OSS 在运行锁下的不同编辑规则。
- quality 容器内 `format:check`、`lint`、`typecheck`、516 项单元/集成测试和完整 `test:e2e` 通过；其中 2 项显式依赖外部 Docker 的测试按既有条件跳过。
- 使用当前本地预览数据卷重建并重启；健康、登录、四个全局设置分组和旧地址跳转均已核对。
