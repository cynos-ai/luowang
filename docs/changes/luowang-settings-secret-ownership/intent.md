# 全局设置凭据归位 Intent

- 日期：2026-10-04
- 状态：已确认实施
- [Spec](spec.md) · [Plan](plan.md)

## 问题

全局设置同时提供“模型与角色”“对象存储”和独立的“全局凭据”。Provider API Key 已经出现在“模型与角色”，又在“全局凭据”重复出现；对象存储的普通连接字段和访问凭据则被拆到两个页面。操作者需要按存储类型而不是按服务寻找配置，且同一 Secret 存在两个编辑入口。

## 期望结果

- Provider API Key 与 Provider、角色模型放在“模型与角色”。
- OSS Access Key ID/Secret 与 Endpoint、Bucket 等放在“对象存储”。
- 取消独立“全局凭据”入口，旧地址进入仍可到达有效设置页面。
- 项目 Git Token、测试账号、密码和清理 Token 继续属于各项目，不与部署级凭据合并。

## 约束

- Secret 继续保存在部署级加密 Secret Store，不进入普通配置、导出文件、URL、日志或页面回显。
- 不迁移、不复制、不删除现有 Secret 数据；只调整编辑入口。
- 保留运行期间 Provider 凭据轮换限制，以及 OSS 凭据用于归档恢复的独立轮换能力。
- 不改变部署级模型与 OSS 被所有项目共用的产品边界。

## 非目标

- 不增加项目级模型或 OSS 覆盖。
- 不修改项目凭据页面。
- 不改变 Secret 加密、作用域、API 或历史 OSS 地址规则。
