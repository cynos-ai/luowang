# 语义判断归属 Spec

状态：已实现并通过本地工程验收；真实模型及 MCP 联合复测尚未运行。本 Spec 覆盖旧需求中按浏览器/视觉/零场景关键词自动判断业务含义的条款，其他边界不变。

## 已有角色决定业务含义

- Main 根据选中场景决定执行是否需要浏览器，在现有 write_plan 调用中显式提供必填 boolean `requiresBrowser`，与完整计划同一次写入。复用 RunContext.browserRequired；不新增场景字段、报告字段、工件或 Session。初始化候选 Main 更新计划时重新决定。声明只代表意图，不证明能力可用或实际执行完成。
- 删除 browserScenarioRequested/browserNeedsVision 自然语言分类器，不按整份计划的关键词调整结果。不要求模型回避某些词语。
- 只有显式需要浏览器时才执行既有 MCP 启用/连通性、环境 URL 检查并向 Runner 提供已配置的 MCP。缺少真实能力仍阻塞，声明不能绕过权限或配置。
- 视觉判断的业务需要由 Main/Runner/Reviewer 按任务判断；Reviewer 实际接收图片前由程序检查其模型的图像输入能力，不用计划关键词决定能力要求。图像模型元数据来自 Provider，不接受模型自报。
- 原始命令、截图捕获、上传/读取完整性及已有图片审核前置保持，不能把声明当成真实证据。Reviewer 独立检查实际执行与必要证据；最终 Main 只汇总 plan/review。

## 零场景与结构校验

- execution_scenarios 仍为唯一执行清单，固定标题、ID 格式、去重、approved 状态、结果顺序严格校验。
- 空清单必须有非空理由，但程序不靠特定语言关键词认可或否定理由；是否真的无需测试由 Main 判断、Reviewer 独立审核，最终 Main 保留审核结果及依据。
- 删除对 plan/review/report 全文的“无需/零场景”等词语验收。非空清单旁提及其他不测试范围，不再因包含这些词而被拒绝。空清单不自动意味着功能测试通过；审核有缺口仍应 blocked。

## 客观故障分类

Provider 的认证/模型不存在分类优先使用明确 HTTP 状态或已定义错误码；超时依赖明确超时类型/错误码。不再用 auth/unsupported/timeout 等宽泛消息词猜具体故障。未知原因返回通用请求失败，不调用其他模型分析，也不回显原始异常或凭据。现有明确 ProviderError 分类保持。

## 保留与验收

保留所有安全正则、机器字段/Markdown 协议解析、Issue 候选检索，不让模型代替授权与完整性检查。

验收：原误判语句不能改变显式执行需求；肯定/否定/其他语言与代码片段不会触发额外分类；缺失或非 boolean 的声明拒绝；真正浏览器需求仍检查 MCP/URL，实际图片仍检查视觉能力；空清单缺理由拒绝、自然语言不限制；Provider unsupported response_format 不误报 thinking；普通/初始化/特殊流程及完整容器工程验收回归。真实模型及真实 MCP 联合复测单独记录，不以 fixture 通过代替。
