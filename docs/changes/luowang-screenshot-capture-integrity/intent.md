# 截图采集完整性与记录如实 Intent

- 状态：需求基线；2026-09-21 已确认协调边界，行为及实施顺序见同目录 spec.md、plan.md
- 关联：[run-evidence-followup](../luowang-run-evidence-followup/intent.md)、#64、#65、#68

## 问题

1. 现有截图护栏在检测到可见非空表单字段时**直接拒绝截图**。实测（2026-09-21 截图稳定状态案例）中，模型为取得截图先行清空表单——取证前改变了页面状态。若被测缺陷恰为"错误页明文回显提交的密码"，该行为会把缺陷证据当场销毁；拒绝机制把"判断问题"变成了"回避问题"。
2. 同一案例 **fail**：execution.md 在声称"未记录字段值"的句子中逐字复述了页面预填的两个合成字段值。根因是页面预填值未进入运行时敏感值集合，既有脱敏只覆盖已登记值。已落地的内联快照字段值登记（`browser-snapshot.ts`）缓解了快照暴露路径，但通过填写提交（如 fill_form）等采集路径的值尚未登记，且缺少"声称未记录却复述值"的反向测试锚点。
3. 含字段值截图在公开报告中由人工把关，但无标签标识，审阅者无法快速识别哪些图包含表单值。

测试环境全程使用合成数据，截图中的"凭据"为合成值；真实网站密码不应明文展示，若展示本身即缺陷，应当被截图留证而非回避。

## 期望结果

- 截图默认照常采集；页面存在可见字段值时**不拒绝**，降级为警告并以标签标识该图含表单值，随证据正常入库。
- 新增硬规则：**禁止为取得或改善截图而改变页面状态**（清空/覆盖表单、切换状态等）。被拒绝的截图作为事实保留，不触发任何状态修改。
- 采集路径上的字段值——快照暴露的与填写提交的——进入运行时敏感值集合，文字工件引用时自动脱敏；识别按控件结构，不按业务含义或名称猜测。
- execution.md 如实描述所见；"声称未记录却复述值"属于**记录失实**，本案例保留为永久反向测试用例，不通过预登记答案或扩大泛化正则使其通过。
- 含字段值截图正常进入 Run 证据与 OSS；保留自动归档，由人工事后审核，不增加发布前门禁（2026-09-21 项目负责人明确选择）。

## 影响

Runner 与共同角色指令、截图护栏（MCP 补丁）、browser-observation/snapshot 证据链路、write_execution 脱敏、相关测试。不改变已成立的功能结论、历史 Run 与工件；live/release 边界独立评估，不因本变更自动解除。

## 约束

- 合成数据铁律不变；不新增任意 JS、任意文件读取或远程写入权限。
- 脱敏识别按控件结构进行，不做全量图片内容审核或泛化正则删正文。
- 不重跑历史轮、不追分；失败与被拒证据原样保留。
- 与 [run-evidence-followup](../luowang-run-evidence-followup/intent.md) 的工程成果（快照字段值登记、写入前脱敏）复用衔接，不重复实现。

## 非目标

- 不做通用图片内容审核、全量泄漏扫描或任意敏感片段识别承诺。
- 不覆盖隐藏字段、封闭 Shadow DOM、Canvas 及动态变化内容的检测保证。
- 不处理真实凭据场景；不部署、不发布、不改写历史报告。
- 不重新评估已合并 change 的验收结论。

## 协调结论（2026-09-21）

1. 随 PR #71 在当前分支实施，不先行合并旧截图方案；旧 change 的已完成工程成果继续复用。
2. 只警告控件结构检测到的可见非空字段，不猜测“疑似真实凭据”；未完成检测如实标示，不推导安全。
3. 证据列表、图片读取结果和报告引用呈现同一检测标签；具体受控字段和验收要求在 Spec 维护。
4. 项目负责人明确选择“保留自动归档，人工事后审核；不新增发布门禁”。没有人工审核事实时不得声称人工已确认。
