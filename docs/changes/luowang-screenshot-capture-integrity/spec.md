- 复用已有 Cookie 关联、Run 隔离、证据哈希、读取失败阻塞、内联快照字段登记与 write_execution 脱敏。旧 change 不再安排“清空后成功截图”的后续案例。

## 采集与状态完整性

- 只适用于已授权的非生产合成测试环境。可见字段非空不拒绝截图，保留原图并返回警告及受控标签；不得将合成字段显示直接判为产品缺陷，具体结论仍依据场景期望。
- 禁止为了取得或改善截图而清空、覆盖表单、切换页面状态，或通过遮挡/裁切隐去待验证内容。按场景执行的正常业务动作仍允许；二者依据动作目的及执行证据判断，不用关键词门禁推断业务语义。
- 检测不修改 DOM、字段值或原图。字段检测异常时标记“检测未完成”并继续尝试截图，不冒充未检测到字段；截图本身失败、浏览器失败及其他工具安全拒绝仍保留为失败，不自动改变页面重试。
- 保留现有控件结构与可见性检测范围，包括开放 Shadow DOM 与可访问 frame；不新增任意 JS/文件/远程写入权限，不承诺检测隐藏字段、封闭 Shadow DOM、Canvas、普通正文或检查后的动态变化。

## 标签与发布

- 截图证据携带字段检测事实：detected、not_detected、unknown。用户标签分别为“页面含可见表单值”“范围内未检测到可见表单值”“字段检测未完成”。标签不含字段原值，不判断值是否为真实凭据，不使用“疑似真实凭据”分类。
- 检测沿用整页保守范围；元素截图的标签描述页面检测事实，不能断言所选区域一定包含字段。标签明确不是全图内容审核或安全保证。
- 标签由真实 MCP/采集链路产生，经既有 Evidence Store 与当前 Run 的具体文件及哈希绑定；文件列表、Reviewer 图片读取结果及报告图片引用处呈现同一事实。不得仅依赖 Runner 自填声明，旧图片无标签记为未知，不推导安全。
- 含字段值截图正常保存到 Run 并上传既有 OSS。保留正常自动归档；项目负责人已明确选择人工事后审核，不增加发布前审批、等待状态或报告 PR。场景变更本来需要审核的流程保持原规则。
- 未发生人工审核时不得声称“人工已确认”；模型读图也不算人工审核。人工事后审核不自动改写原报告或图片。

## 文字保护与记录准确性

- 复用内联快照登记，补齐填写操作输入中的结构化字段值登记，覆盖固定 adapter 实际提供的 fill_form/type 等填写入口；按控件/工具参数结构判断，不按字段业务名称猜测。值仅留在既有 Run 内存敏感值集合，后续文字证据与 write_execution 自动脱敏。
- 登记在填写操作可能使用该值前完成。登记/格式校验失败不得静默放行输入并宣称受保护；实际操作、失败及登记范围分别记录。登记不证明提交成功，也不证明服务器收到该值。
- 不改页面真实内容以实现文字脱敏，不将截图像素按文本规则删除。原值未被观察/登记、部分值或任意敏感片段不在保证范围。
- execution 如实记录观察与限制，不得在“未记录”的句子中复述值。自动脱敏只能证明输出保护，不证明模型声明真实；永久保留旧反例，分别检查 writer 输入、落盘结果和原始观察。

## 验收

- AC-CAPTURE-01：真实 MCP 对预填合成页面照常截图，前后字段和错误状态不变，原图保留能复现问题的内容；含明文回显的缺陷页面也不因取证而被清空。
- AC-CAPTURE-02：detected/not_detected/unknown 均有真实回归；检测异常不伪报安全，截图真实失败不伪报成功。标签与 Run、图片字节关联，列表、读取、报告引用一致。
- AC-CAPTURE-03：固定填写入口的值在文字工件脱敏，两个 MCP 入口、异常路径和跨 Run 隔离有测试；旧公开源码常量模型测试不由预登记答案替代。
- AC-CAPTURE-04：角色不为截图修改现场，原“未记录却复述”样本永久保留为反例。零模型保护和真实模型行为分别验收，不能用脱敏后的文本替代对模型原始声明的判断。
- AC-CAPTURE-05：原图正常 OSS 上传与自动归档，标签不新增审批门禁；完整容器质量、原生 MCP 预检通过后再安排有界新模型评估。live/release 和人工质量评分仍独立，不因本 change 自动通过。
