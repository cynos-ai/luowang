# 模型设置交互收尾 Spec

- 日期：2026-10-04
- 状态：已确认
- [Intent](intent.md) · [Plan](plan.md)

本 Spec 覆盖 `luowang-adaptive-thinking-oss-settings/spec.md` 中“Final Main 使用最低档”和“持久化 Thinking 偏好不参与运行”的旧规则。

## 1 Thinking 配置

- Main、Runner、Reviewer 各显示一个 Thinking 下拉，只列当前目录模型实际支持的档位。
- 首次选择或切换模型时，Main 与 Reviewer 默认选择第二低档，Runner 默认选择最低档；只有一个档位时均选择该档。
- 已保存且仍受当前模型支持的值保持不变。旧值不受支持时，页面展示并在下次保存时持久化角色默认值。
- Main 与 Final Main 共用 `agents.main` 的模型及 Thinking，不提供独立配置。
- 连接检查和真实 Session 使用相同解析规则：有效的已保存值优先，否则按上述角色默认值回退。

## 2 Provider 与模型选择

- 模型来源支持配置多个独立来源。每个来源拥有稳定 ID、Provider 类型、Base URL、独立 API Key、最近验证时间和验证成功时取得的模型目录快照。页面使用 Provider 名称和 Base URL 域名自动生成辨识标题，不要求操作者另填来源名称。
- 旧版单 Provider 配置自动映射为第一个模型来源；原有 API Key 继续可用，迁移不得在页面、日志或响应中回显明文。
- 来源只有在凭据与连接验证成功后才向角色提供模型。修改 Provider、Base URL 或 API Key 后立即清除旧验证状态，避免继续选择陈旧模型。
- API Key 保存后，来源卡改为只读，避免把既有密钥误用于被修改后的 Provider 或 Base URL。待验证来源只提供验证与删除操作，验证成功后只提供删除操作；需要更换配置时删除后重新添加。
- 角色模型选择聚合所有已验证来源的模型并显示来源名称；保存时同时记录来源 ID 与模型 ID，允许三个角色使用不同来源。
- 删除来源必须先通过站内弹窗确认；确认后立即保存删除结果、清空引用它的角色模型并删除该来源的加密凭据，成功或失败通过 Message 反馈。尚未保存的新来源只从当前草稿移除并明确提示。
- Provider 与角色模型使用同一套样式化组合框，支持输入过滤、鼠标选择、上下键、Enter 和 Escape。
- 组合框首次展开时显示全部候选项；只有用户开始输入后才按输入内容过滤，当前值不得让列表退化为单项。
- 组合框具备 combobox/listbox/option 语义，并保留手工输入未知值的能力。
- 成功载入模型目录不显示整行提示。加载和错误状态紧凑展示；错误仍可被辅助技术读取。
- 模型能力以带名称和悬浮说明的实心分色图标表示文本、视觉和推理能力，不使用类似按钮的边框，不重复占行显示模型名称。

## 3 标题、帮助和 Secret

- 三个角色标题显示为“测试组长”“测试工程师”“质量审核员”。质量审核员的视觉要求通过可聚焦问号帮助说明。
- Provider API Key、OSS Access Key ID 和 OSS Access Key Secret 在输入框内部表达是否已配置；状态不另占一行，清除操作与输入同行。
- 已配置 Secret 的占位提示为“已配置 · 输入新值可轮换”，未配置时为“输入凭据”。原值始终不回显。
- 管理员菜单入口使用圆形头像表达，保留账户设置和退出功能。

## 4 通用选择控件与浏览器工具

- 非输入型枚举选择使用统一的样式化 SelectBox，Thinking 和 OSS 访问模式不再显示浏览器原生 select。
- Thinking 字段显示名称为“思考等级”。
- 全局设置中的“浏览器”分组显示为“浏览器工具”。当前部署镜像和运行时固定使用无界面 Chromium，因此页面只展示“Chromium · 无界面”，不提供无法生效的浏览器类型及 Headless 开关。
- 浏览器操作超时允许 `5000–120000` 毫秒，步长 `1000` 毫秒，页面建议值为 `30000`；前端输入约束与服务端归一化规则一致。
- 设置分组不重复提供“查看最近连接状态”入口；依赖检查仍由系统状态页承载。
- 页面内的未保存离开、清除凭据、配置导入、Git 引用输入和重试归档统一使用罗网站内弹窗，不调用浏览器原生 `confirm` 或 `prompt`。刷新和关闭页面不弹出无法定制样式的浏览器确认框。
- SPA 入口 HTML 返回 `Cache-Control: no-store`，确保本地预览和部署更新后刷新即可取得当前带哈希的前端资源。
- 操作成功、失败和普通反馈使用主导航下方居中的轻量 Message 浮层，不占用页面布局；成功、错误、警告和信息使用与罗网视觉一致的独立色彩、图标和浅色背景，提示自动消失，并允许操作者立即关闭。
- 所有改变系统状态的操作都必须在完成后给出成功或失败 Message，包括保存、验证、检查、同步、启停、重试、清除和删除。危险或不可恢复操作必须先使用站内确认弹窗；只读导航、筛选和展开收起不显示完成反馈。
- 新增模型来源执行验证前，先把包含 `modelProviders` 的模型分组配置保存，再保存该来源的独立密钥，最后请求模型目录；任何阶段失败都显示该阶段的真实错误。

## 5 共享 UI 组件

- 通用交互通过 `src/web/components/ui.ts` 提供稳定入口；页面优先组合 Button、Message、Dialog、Prompt、Field、SelectBox、ComboBox、StatusLabel、DataTable 和 PageHeading，不重复实现同类控件。
- 组件 API 表达用途、状态和危险等级，罗网当前视觉由共享 token 与组件样式决定。主题切换只调整 token 和共享组件，不要求业务页面重写颜色、边框、阴影或动效。
- 新增页面不得直接使用浏览器原生确认、输入弹窗或 select；现有原生 select 按页面改造批次迁移，不在本轮为追求目录统一进行高风险全量替换。
- Button、Dialog 和 Message 等组件必须保留键盘、焦点、语义和辅助技术状态。

## 6 共享依赖自动检查

- 模型来源、角色模型或 Provider 凭据变更后，在配置保存响应之外异步刷新模型 Provider 快照；浏览器工具和 OSS 配置或凭据同理只刷新受影响的依赖。
- 服务启动后检查缺失或超过 30 分钟的共享依赖快照，之后每 30 分钟检查一次过期快照；同一依赖的后台检查不得重叠。
- 自动检查失败更新真实检查快照或写入服务日志，但不把已经成功的配置保存回滚为失败；日志和页面不得包含 Secret。
- 系统状态页每 30 秒只读刷新持久化快照，不因打开页面而连接外部服务；页面说明自动检查规则，并保留“立即检查”。后台检查不显示前端 Message。

## 7 验收条件

- AC-MSP-01：三个角色的 Thinking 选项与当前模型支持档位一致，切换模型应用角色默认值，保存的有效选择用于连接检查与真实 Session。
- AC-MSP-02：Main 与 Final Main 使用同一模型和 Thinking；旧的无效档位自动回退且不阻塞。
- AC-MSP-03：Provider 和模型组合框支持键盘、鼠标、过滤和未知值输入，且无原生 datalist。
- AC-MSP-04：目录成功提示不占行；能力图标和 Reviewer 帮助可由鼠标及键盘理解。
- AC-MSP-05：三个部署级 Secret 的配置状态内联，原值不回显，保存、轮换、清除和锁定规则保持。
- AC-MSP-06：管理员入口呈头像样式；768、1024、1440 像素宽度无横向溢出或字段错位。
- AC-MSP-07：相关单元、UI workflow、完整质量门通过。
- AC-MSP-08：组合框展开显示完整候选，开始输入后再过滤；Thinking 和 OSS 枚举使用统一 SelectBox，箭头对齐且具备键盘操作语义。
- AC-MSP-09：浏览器工具页固定展示无界面 Chromium，超时只接受 5000–120000 毫秒，设置页不再重复显示连接状态入口。
- AC-MSP-10：源码不再调用浏览器原生 `confirm`、`prompt` 或 `alert`；未保存导航和危险操作使用可键盘操作的站内弹窗。
- AC-MSP-11：可新增、编辑、验证和删除多个模型来源；各来源凭据独立加密保存，三个角色可从全部已验证来源选择模型，运行时使用所选来源。
- AC-MSP-12：设置操作反馈以顶部 Message 浮层显示且不改变页面布局；新增来源可按配置、密钥、验证的顺序完成，不会因漏存来源而返回“模型来源不存在”。
- AC-MSP-13：危险操作统一使用罗网站内确认组件；所有状态变更操作完成后显示成功或失败 Message。
- AC-MSP-14：通用 UI 组件具备统一导出入口，页面新增交互优先复用共享组件，主题视觉由 token 与共享样式集中控制。
- AC-MSP-15：共享依赖在相关配置变更后异步检查，缺失或超过 30 分钟的快照由后台周期刷新；自动检查防重入且不延迟配置保存响应。
