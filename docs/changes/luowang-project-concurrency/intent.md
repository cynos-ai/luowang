## 问题

罗网已经按项目管理仓库、配置、凭据、执行镜像、场景和 Run，但全局仍只允许一个请求进入准备和执行。一项耗时的规划、浏览器操作或镜像准备会让其他项目等待，即使这些项目的测试环境和执行资源彼此独立。使用者无法同时推进多个项目的测试。

控制台也按一个当前 Run 展示执行状态和全局队列位置。仅放开后台限制，会造成正在执行的任务显示不全、等待原因不准确，以及恢复和清理遗漏。

同时存在两个明确的界面缺陷：[#118](https://github.com/cynos-ai/luowang/issues/118) 模型设置目录状态挤占角色卡片网格、[#119](https://github.com/cynos-ai/luowang/issues/119) 768px 视口出现整页横向滚动。[#94](https://github.com/cynos-ai/luowang/issues/94) 已有 Git 超时实现和专项测试，但从底层到就绪页面的错误传递还需要核验，不能按开放 issue 数量重复开发。

## 期望结果

- 不同项目可以同时测试；一个项目的慢任务或局部失败不会占住其他项目全部执行机会。
- 同一项目继续按请求顺序执行，保持目标提交、场景资产、测试数据和归档的一致性。
- 操作者能看到所有正在处理的项目、各自进度及真实等待原因。
- 并行时仍能证明凭据、浏览器状态、证据、报告及清理对象归属正确，重启后不重复执行或错误推进。
- 现有明确布局缺陷得到修复，已有 Git 超时能力得到完整核验。
- 通过有限的并发负载了解部署容量，不把更多并发等同于无限吞吐。

## 影响与约束

影响同一操作者管理多个可信项目的日常使用，以及队列、任务生命周期、共享配置保护、控制台和真实验收。保留单实例、单管理员及各项目的非生产环境边界，不引入分布式平台。

正常 Run 仍使用 Main/Runner/Reviewer 三组配置、四个隔离 Session。角色权限、固定 target、场景 patch allowlist、审核证据、自动归档和 Harness 独立清理规则不变。并行能力不得以复用会话、放宽 Secret 边界或改写历史报告为代价。

已有本地材料可供复用评估，历史交替 Run 不能证明新候选的并行执行。新 live 必须固定候选、目标和资源范围；Secret 继续留在受控位置。

负责人已明确授权完成整个 Plan，模型费用由外部金额限制控制，本轮不另设调用次数上限。授权包含 Plan 指定的两个外部非生产目标；不包含版本发布、tag 或 Release。

## 非目标

- 同项目多个 Run 并行、多环境矩阵、多用户、分布式 worker 或通用工作流引擎。
- 安全停止运行：保留为后续候选，不纳入本阶段验收范围。
- #93 Git 受控代理、#104 Git 自动重试、#103 跨候选证据复用和 #95 模型质量对照。
- 整体 UI 重构、依赖升级、历史数据清除、自动修复产品代码。
- 自动部署被测产品、自动隔离目标应用的共享数据库或共享测试账号。
