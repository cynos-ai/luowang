# 项目执行服务器与应用启动 Spec

- 日期：2026-10-05
- 状态：实施中；2026-10-06 已明确采用受信任自部署边界，复用现有执行链并放宽普通项目兼容性。
- [Intent](intent.md) · [Plan 与评审结论](plan.md)

## 1 范围和规则衔接

本需求实施后覆盖连接资源 Spec 的“远程执行和文件注入尚未启用”，扩展多项目 Spec 的“不自动启动被测应用”。保留项目并行、运行可靠性、单向交接、模型语义判断、证据与截图完整性的其他约束。当前生效规则不因本建议稿落盘而改变。

正常 Run 仍为三组 Agent 配置、四个隔离 Session；初始化与场景审批分流保持，不启用 Pi Skills。执行端不运行模型角色，不改变 Git/OSS 和正式报告的所有权。

## 2 执行位置与固定身份

- 首版支持 Linux Docker Engine；Compose 模式要求受支持的 Compose v2 插件。控制端仍可采用现有 Docker 部署。
- 本机指控制端所连接的本机 Docker Engine，不是往罗网服务容器内部安装第二个 Docker daemon。远程连接目标服务器自己的 Docker Engine。
- 每项目绑定一台服务器，未绑定映射为稳定的本机执行身份；禁止通过远程失败回退本机、轮换地址或改投其他服务器。
- 入队固定非 Secret 运行配置、服务器 ID/执行位置修订、受控文件 ID/版本引用；认领后沿用既有 prepared/resolved 流程固定 target。后续页面切换不改变任务上下文。
- 副作用开始前登记资源所有者：instanceId、projectId、queueId、attemptId；Run 创建后关联 runId。尚未解析 target 或尚无 Run 时记录 null，不能为构建预检制造假 Run。
- Run 记录实际服务器身份、固定 target、配置修订、启动定义摘要、已解析镜像身份、场景 patch 摘要和资源回执。Secret 明文和可离线猜测 Secret 的公开内容摘要不进入快照、报告或标签。
- 项目有 queued/running/waiting_archive 时继续禁止改变运行语义绑定；有未核清资源时也禁止删除服务器、改投主机或更换项目执行位置。仅为恢复原端点而轮换认证凭据的受限流程，需与普通绑定变更分开验证。

## 3 项目模式与配置

| 模式 | 应用生命周期 | 地址与要求 |
| --- | --- | --- |
| 罗网启动项目 `managed` | 在绑定服务器启动单应用或 Compose 服务栈 | 本 Run 就绪后生成，用户不必预先部署 |
| 已有测试环境 `external` | 不启动被测应用；仓库命令仍在绑定服务器执行 | 保留非生产 URL 和已有清理契约 |
| 仅仓库测试 `repository-only` | 仅启动受控命令环境 | 无应用地址；显式 requiresBrowser=true 时保留 blocked |

新建项目默认 managed，缺启动配置时保存为 paused，不能猜测配置并启用。已有项目迁移为 external（包含空 URL 的未完成项目，继续显示缺项），不自动启动服务；选择 repository-only 或 managed 必须是明确配置变更。

保留内置执行镜像/仓库 Dockerfile 入口，新增运行模式与 `single-container | compose` 启动方式。单容器需要明确工作目录、初始化/构建与启动入口、服务端口、健康检查路径/超时；Compose 需要仓库相对文件路径、启用服务集合、应用入口 service/port、测试命令执行 service 和健康检查配置。自动识别只给建议，经保存后才成为事实。

内置 Node 镜像当前只是工具链基线，不自动安装依赖或编译项目。依赖准备、应用编译与启动应有明确步骤和日志；仓库 Dockerfile 的 ENTRYPOINT/CMD 只能在明确选择使用镜像入口时执行，不能继续无条件覆盖为 sleep 后声称已启动应用。

健康检查只证明可访问，不证明业务通过；状态和失败原因来自真实退出码、响应或超时，不能解析模型文字推断。模型计划继续通过 write_plan 的 boolean requiresBrowser 声明需求。

项目就绪应区分公共必需能力和模式特定能力。repository-only 不因浏览器未配置而一律无法启用；Main 取得真实能力状态，后续显式浏览器需求仍按原规则阻塞。现有 readiness-adapters 把浏览器检查归入部署必需项，该处也必须修改，不能只取消 baseUrl 的必填检查。

## 4 Compose 首版契约

- 单应用与 Compose 共用资源登记、服务器容量、取证和恢复；一套 Compose 服务栈占一个项目执行名额，同时对各服务设置资源约束，不能把“1 个项目”等同“1 个容器”。
- 从固定提交读取 Compose 及引用的 Dockerfile/构建上下文。由所选执行服务器的 `docker compose config` 解析合并、profiles、`env_file`、build args 和变量，再生成受控运行定义；解析过程不继承任意服务器业务环境，只使用 Docker 连接所需环境和固定项目目录中的明确配置。解析结果可能包含 Secret，不写日志、报告或持久配置。
- 支持多个 service、本地受控 build context 或固定外部镜像、内部服务发现、depends_on、healthcheck、Run 专属网络与命名卷。服务发现使用原 service 名；测试命令只能进入固定的测试 service。
- 外部镜像 tag 首次准备时解析并固定实际 digest；重启恢复不重新解析移动 tag。可复用构建镜像按服务器、平台、固定提交和构建定义摘要核验。
- 普通 Compose 字段默认沿用原生解析结果。继续拒绝 privileged、Docker socket/设备挂载、host network/PID/IPC、越界或绝对宿主路径、external 网络/卷和外部构建上下文；这些限制用于避免越过 Run 归属和误清理，不扩展为恶意模型沙箱。
- 显式 container_name、固定网络/卷 name 和固定宿主端口不得原样执行。受控定义统一生成本 Run 名称和入口映射；固定应用端口转换为动态宿主端口，其他服务不对宿主机发布端口。
- 相对源码 bind mount 必须映射到本 Run 的受控副本，校验所有父路径及链接；默认只读，确需写入的工作目录使用本 Run 可写副本或卷。只允许已登记资源，不能直接接受模型提交 Compose 文件或宿主挂载参数。
- 所有服务/网络/卷带实例与任务归属，启动前记录确定性名称及预期标签。清理先逐项核对实际归属；不能对用户原始项目目录直接执行 `compose down -v` 或按名称前缀批量删除。
- Compose profiles、`env_file`、build args、depends_on 和常见服务字段由原生 Compose 解析。多文件集合仍需项目显式保存；不支持的能力不能被误记为 Docker 故障。

## 5 执行接口与源码、镜像

复用 image-source、run-source、image-preparation、execution-container、command-session 的职责，增加面向 build/create/start/exec/inspect/logs/remove、文件传输及访问通道的受控接口。本地和 SSH adapter 使用同一所有权契约；模型不获得宿主机 Shell、SFTP 或 Docker 工具。

Runner 可以在本 Run 固定的命令容器或 Compose command service 内通过 `/bin/sh -lc` 执行项目脚本、管道和项目镜像已有工具，不维护可执行文件白名单。罗网继续固定容器、工作目录、Run 环境变量、超时、取消和输出上限。命令取消或通道断开后必须停止该命令服务或核对进程已退出，不能把客户端断开当成容器内进程已经结束。

可复用构建输入是固定产品提交与构建定义。场景 patch 继续经原 allowlist 校验，仅覆盖 Run 源码；受控文件在镜像构建完成后注入。禁止把带 patch/Secret 的运行目录拿去构建通用缓存镜像。

镜像缓存至少包含 serverId/执行位置修订、projectId、targetCommit、buildDefinitionHash、platform；Compose 按需增加 service/build 身份。Docker image ID 是所选 daemon 上的内容 ID，不代表该镜像存在于另一台服务器。每次复用都在选定 daemon 核验不可变 ID 和标签。

首次登记外部操作意图必须先落库，再发命令；响应丢失后按登记和实际 inspect 核对，不盲目重复创建。构建、文件上传、日志读取都有大小和时间上限、中止传播与结果不确定分类。

## 6 网络和 Run 级运行环境

- 新增由 Harness 拥有的 Run 级运行环境，将模式、实际 baseUrl、能力状态、测试入口和清理目标传给环境工具、HTTP、浏览器及能力检查；不能通过改写共享项目 baseUrl 传递临时地址。
- 远程：应用在容器内监听可被入口转发访问的地址；执行主机仅发布到自身回环的临时端口。SSH 转发的本地监听端必须与 Harness HTTP/MCP 浏览器位于相同网络命名空间，并只绑定回环。
- 本机：针对原生进程部署与 Compose 部署各提供可验证路径。控制端在容器内时可使用仅供本 Run 的桥接网络与受控转发；不能把 daemon 宿主机 127.0.0.1 当作浏览器的 127.0.0.1，也不能以开放 0.0.0.0 公网端口解决连通性。
- Compose 服务间地址与控制端浏览器入口地址分别记录。动态 origin 会影响 Cookie、WebSocket、回调地址和 OAuth；支持的单入口 HTTP/WebSocket 路径需实测，依赖固定公网回调的应用可继续使用 external 模式。
- 受控 HTTP 保留 Run 入口限制。浏览器允许当前 Run 入口以及项目显式配置的外部来源，以覆盖 CDN、第三方登录和多服务应用；转发仍只能连接已登记入口。访问范围必须真实生效，不能只写在 Prompt 中。
- 隧道断开后停止依赖该通道的新操作，记录基础设施缺口，保留已确认业务结果；不改用旧项目 URL，也不把网络故障自动判为产品 Bug。

## 7 凭据、受控文件与 SSH

- 复用 Secret Store，文件只注入配置中明确选择的 service/路径；路径、UTF-8 字节大小、总量、父路径、符号链接和已存在目标冲突在实际执行端再次验证。首版目标冲突拒绝覆盖，给出配置修改建议；不改写 Git 源树。
- 受控文件只用于临时运行副本/卷，不进入 Git、构建上下文、镜像层、模型通用源码工具、配置导出或归档。原文件扩展名不作为授权依据，内容不回显。
- 注入文件保持 `0600`，归属目标容器配置的运行用户；Compose 显式 `user` 优先于镜像默认用户，源码卷的临时注入容器也须沿用该用户。非 root 服务必须能在首次启动时读取文件，不通过放宽所有人读取权限或改用 root 运行应用解决。
- SSH 主机指纹必须经管理员核对并固定；首次未确认和指纹变化都停止认证，不以自动接受未知主机密钥代替验证。私钥/密码不进入 argv、日志或远程命令文本，不转发控制端 SSH agent。
- SSH 无常驻 Worker，但需可测试的命令编码/参数传输与 SFTP。Shell 插值、选项注入和 tar 路径/link 攻击属于 adapter 测试边界，不能假定远端 exec 天然支持 argv。
- Git 拉取留在控制端，优先传不含 `.git` 的固定源码包，远端不需要 GitHub Token；模型/OSS/控制端主密钥不传执行端。
- 从注入前开始登记需要脱敏的值，覆盖进程输出、Compose 错误、日志、HTTP、浏览器文本和模型交接。多行配置不能只按整份全文替换；常见 env/JSON/YAML 标量及跨流分块需专门验证。无法安全处理的原始输出拒绝保存，保留安全诊断。不得宣称能自动识别任意编码后的秘密。
- 清理删除临时明文及资源，不声称磁盘物理擦除。若凭据轮换用于恢复，同一固定端点和资源身份不变，不能重新启动测试。

## 8 生命周期、容量与恢复

保留 SQLite Queue/Coordinator/Dispatcher；在单个认领事务中检查全局上限、服务器名额、项目状态和项目互斥，全部满足才认领，避免先占全局名额再排队等服务器。选中服务器不可用/已满时跳过该项目，继续轮转其他合格项目。手动镜像准备、接入启动探测也必须使用同一准备资源登记与服务器额度，不能绕过 Run 队列形成无限制构建旁路。

本机也有服务器容量，默认跟随当前全局上限；新增远程服务器建议默认 1，可在线调整。降低上限不杀已有任务。容量不是 CPU/内存保证，Compose 服务总资源要检查并在验收中测量。

应用与命令环境由 Run 生命周期 owner 持有；Runner 结束先冻结和上传必要证据，Reviewer/最终 Main 保持原权限，最终 Main 后先做依赖应用的业务数据清理，再关闭应用、隧道、网络、卷和工作目录。不能继续把应用容器的销毁放在 Runner Session 的 finally 中。

取消、异常和初始化多轮使用同一请求下明确的 attempt 归属；不自动重跑模型，不让侦察和正式验证容器相互覆盖。应用健康失败为执行条件不足，构建前失败记录在请求，不能伪造产品测试结果。

资源登记状态可为 planned/created/cleanup_pending/unknown/released，属于基础设施事实，不是第五种 Run 业务结果。远程断线后有界结束当前网络调用，持久化 unknown、暂停该服务器的新认领，后台限频核对本实例资源；重启按服务器恢复，不运行全局模糊清理。

**推荐首版沿用真实占用规则**：未确认计算资源退出时，继续保留全局及该服务器占用与项目互斥；其他服务器只能使用剩余名额。后台恢复替代无界阻塞的调用栈，不等于释放容量。原稿“一个服务器故障不能占住全局全部容量”应改成此有条件保证；若需放宽全局硬上限，须另外确定语义和验收。

已确认资源退出后才释放执行占用；waiting_archive 继续不占执行名额、仍阻止同项目下一请求。清理失败/未知单列告警，不改变已经成立的功能结论；无法完成必要验证仍按已有 blocked/interrupted 规则处理，不能把所有断线统称 failed。

## 9 迁移、页面与交付

- 使用下一条离线迁移，不能重写已经应用的 0021。先备份、隔离副本演练，再核验外键、幂等和回退；旧程序不直接打开新 schema。
- 旧镜像记录保留并注明历史本机来源；新缓存经新键重新核验。历史 Run 不回填当前服务器绑定，不改写 target、镜像、报告和证据事实。
- 旧的远程绑定升级后先显示“待验证，尚未远程执行”，明确完成运行设置和准备检查后才能启用新执行能力，不能因升级突然向远程服务器发送项目命令。
- 升级前优先排空执行；已有 queued/prepared/resolved/待归档快照按旧 external 和历史本机语义迁移或保留只读解释，不按当前远程绑定重写。保留 prepared commit/internal ref，不重解析移动 HEAD，不重新运行已停止请求。
- 服务器页显示检查时间、SSH 指纹/连通、Docker/Compose/平台、磁盘、容量和未知资源；后台检查不产生反复 Message，不因页面读取触发外部操作。
- 接入按仓库与服务器、场景规则、运行模式/Compose/文件、准备与启用组织。Token 只在资源选择处出现；测试账号和清理配置为独立可选项，所有状态变更反馈沿用共享 UI。
- readiness 检查和显式启动探测分开：普通状态读取不部署应用；启动探测有进度、停止与回收，消耗容量但不生成正式测试结果。Run 仍对固定 target 再准备。
- Run 页显示真实服务器、服务/入口、阶段和资源清理状态；临时地址标明仅运行期间有效。正式证据用已有持久地址，不能把过期隧道 URL 当证据。

## 10 验收条件

| ID | 完成要求 |
| --- | --- |
| AC-ES-01 | 本机和远程均在指定 daemon 执行，无静默回退；服务器/修订随任务固定，历史不重写 |
| AC-ES-02 | 三种模式迁移与就绪正确；repository-only 无 URL 可执行，requiresBrowser 缺能力仍 blocked |
| AC-ES-03 | 单容器完整启动、健康、浏览器与 HTTP、应用仍存活时的业务清理和最终资源回收通过 |
| AC-ES-04 | 本机和远程 Compose 多服务、依赖、profiles、env_file、build args、内部 DNS、临时卷、固定测试 service 完整流程通过 |
| AC-ES-05 | Compose 由目标端原生解析；危险宿主配置拒绝，固定端口转换；不同 Run 的名称、端口、网络、卷不冲突 |
| AC-ES-06 | 镜像不跨服务器误复用，产品构建与场景 patch/Secret 注入分离，固定 digest/配置可追溯 |
| AC-ES-07 | 首次未知/变化 SSH 指纹拒绝，凭据最小暴露，参数/路径注入、伪造归属与跨项目操作拒绝 |
| AC-ES-08 | 文件只注入选定服务；越界、链接、冲突、超限拒绝，镜像/日志/证据/Git 无合成 Secret 泄露 |
| AC-ES-09 | 原生及容器化控制端均可访问正确应用；HTTP/WebSocket、断隧道、origin/Cookie 隔离有实证 |
| AC-ES-10 | 全局+服务器原子容量、同项目串行、轮转、手动准备计额和在线降额不超卖、不假释放 |
| AC-ES-11 | 创建回执丢失、构建/健康失败、取消、SSH 断线、控制端重启均能核对未知资源，不误删/重复执行 |
| AC-ES-12 | 资源未知时真实占用和告警保留，有空闲名额的其他服务器可执行；清理失败不改已成立结果 |
| AC-ES-13 | 旧数据副本迁移/回退、项目/Run/证据归属、旧 external 行为以及 768/1024/1440px UI 验证通过 |
| AC-ES-14 | 同一候选完成 quality/local、runtime MCP 及一台真实远程服务器上的单容器+Compose+容器内 Shell 联合验收，证据分层记录 |

实现进度和已完成检查以 Plan 为准；真实远程完整流程尚未验收，不能据本机检查宣称整体完成。
