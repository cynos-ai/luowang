# 代码深读与测试判断 Intent

- 状态：v0.6.0 需求基线。负责人已确认 Skill 由罗网内置、随版本维护，参考 cynos-ai/engineer onboard，并于 2026-09-23 授权编写 [spec](spec.md) 与 [plan](plan.md)，随后授权继续实施；完成范围见 plan，版本尚未发布。
- 日期：2026-09-23
- 基线：v0.5.0；本版独立完成代码深读，[多项目管理](../luowang-multi-project/intent.md) 后移至 v0.6.1，不作为本版前置条件。

## 问题

Main 已能读取固定提交的文件、搜索源码、查看 diff，并在初始化时结合 Runner 侦察形成场景。现有方法要求关注调用方、共享状态和业务风险，但仍需加强如何从入口追到核心逻辑、如何核实理解依据、如何把阅读发现转化为场景维护判断。

读取目录、入口或若干搜索结果不能证明已经理解业务。只按当前实现生成期望，可能把缺陷固化为测试；只按改动文件选择回归，也可能遗漏共享权限、持久化和异步处理中的影响。本需求旨在降低这些风险，不把它们一概写成已复现的产品缺陷。

## 已确认的方向

- 代码深读方法属于罗网内置 Skill，由罗网随版本维护。
- 服务于测试集初始化及后续维护判断。
- 参考 cynos-ai/engineer 的 onboard 逻辑，不直接执行该工程实践或引入其全部职责。

## 期望结果

1. 初始化能从入口追踪关键业务规则、角色权限、状态变化、数据存储和外部依赖，说明主要流程、异常路径、测试前置及未覆盖部分。
2. 维护能结合固定 base/target 的变化，追踪相关调用及共享状态，解释场景复用、新增、修改或废弃的理由；纯重构不制造无意义场景变更。
3. 理解结论有可追溯来源，区分已确认规格、当前实现、已有测试和运行观察；冲突与未知保持可见，不以实现替代业务期望。
4. 能区分已读取、部分读取、未读取及读取失败。成功读取不能直接证明理解正确；覆盖充分性仍需语义判断和独立审核。
5. 判断测试条件时区分已有可用命令、仅存在但未验证可运行的命令及建议补建的能力，避免将不存在的测试命令或未经执行的观察写成事实。
6. 同一个项目的理解始终关联具体提交；未来若复用理解，须识别源提交和变化造成的失效，不能跨项目或无条件沿用。

## 影响与约束

- 涉及 Main 规划方法、初始化交接、受控源码读取事实、独立审核、资源构建和质量评测。
- 内置资源需要可识别版本并可追溯到 Run，具体加载机制在 spec 确定；“内置 Skill”不自动意味着开启 Pi 的宿主机或仓库 Skill 发现。
- 现行 production-closure 规格规定不使用 Pi Skills。新 spec 需明确术语与覆盖范围，保留角色隔离、受控工具及资源来源约束。
- 沿用已确认业务期望、不弱化断言和模型负责语义判断的边界；不以确定性格式检查宣称理解正确或覆盖完整。
- 沿用场景 patch、正式报告和 Secret 的现有权限。保持填写态截图及报告自动归档、人工事后审核的既定选择。

## 非目标建议

- 用户上传或按项目安装任意 Skill；自动加载目标仓库中的 Agent 指令。
- 接管工程开发、代码修复或发布规范维护。
- 为每次 Run 创建永久调用图、目录台账或另一套场景资产。
- 把“读完若干文件”或“生成更多场景”作为效果证明。

## 验收方向建议

使用相同项目快照、变更和模型配置进行前后对照，覆盖初始化、纯重构、Bug 修复、新能力、权限/持久化变化、明确废弃、规格与实现冲突及测试条件不足。预先固定关键风险、禁止编造的期望和维护判断依据，比较重要遗漏、错误期望、无谓变更及模型成本，保留失败与未完成结果；工程测试与真实模型质量评分分别报告。

## 规格衔接

内置资源加载、读取事实、计划引用与角色交接，以及模型效果验收规则已细化到同目录 spec；实施顺序和完成证明见 plan。本 intent 中的参考取舍保留其来源，具体执行以 spec 为准。实际评测输入及每批资源上限在实施时冻结，不把本次文档授权当作无限模型预算。
