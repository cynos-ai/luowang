# 系统状态检查反馈 Spec

## 1. 检查接口

- `POST /api/system/checks/:checkId` 返回 `SystemCheckResponse`：
  - `check`：本次检查后持久化的 `SystemDependencyStatus` 快照。
  - `result`：本次检查的实时结果 `ConnectivityResult`（含 `status`、`message`、`checkedAt`、`latencyMs`）。
- 能力未启用时（浏览器 MCP 关闭、OSS 未配置等），`check` 保持原有快照，`result` 说明未启用原因；不写入新的持久化记录。
- 可执行检查写库后，`check` 反映本次结果；不再要求客户端额外重新加载才能看到新状态。
- 无效 `checkId` 仍返回 400，未认证仍返回 401。

## 2. 页面反馈

- “立即检查”完成后：
  - 行内状态标签、消息与时间更新为 `check` 的内容（本次检查结果优先于打开页面时的快照）。
  - 当 `result.status !== 'ok'` 且 `result.message` 与 `check.message` 不同（即未写入的原因），在行内显示该消息。
  - 请求失败（HTTP 错误）时在行内显示错误文本，角色为 `alert`；不使用页面顶部通知。
- 未启用能力的行内提示必须让用户知道“检查没有失败，而是能力未启用/未配置”，并保留“设置”入口。
- 每行的检查、加载与错误互不影响；检查其他行时不清空已有结果。
- 检查成功后行内状态可直接变为“正常/失败”等真实结论，无需额外刷新页面。

## 3. 样式

- 行内提示使用警示红与加粗文字，位于该行消息下方；与现有 `--lw-red` 对比度要求一致。
- 不新增弹窗、抽屉或全页横幅。

## 4. 验收条件

- **AC-SCF-01**：未启用能力的检查返回 `check`（原快照）与 `result`（未启用原因），页面在行内显示该原因。
- **AC-SCF-02**：可执行检查完成后，页面行内立即显示 `check` 的最新状态与时间，无需第二次请求。
- **AC-SCF-03**：检查请求失败时，页面在对应行内显示错误文本，页面顶部不再作为唯一提示位置。
- **AC-SCF-04**：多行检查互不干扰；单行失败或未启用不影响其他行显示。
- **AC-SCF-05**：`format:check`、`lint`、`typecheck`、单元测试与浏览器 E2E 通过。
