# 系统状态检查反馈 Intent

## 当前问题

在“系统状态”页点击“立即检查”后，可能看不到任何结果：

1. 对应能力未启用（浏览器 MCP 关闭、OSS 未配置）时，后端返回“尚未提供”类结果但不写入记录；页面只重新读取快照，行内仍显示“未检查/无真实记录”，也没有任何提示，看起来像点击无效。
2. 检查请求真正失败时，页面只在页面顶部显示错误通知；用户正停留在列表中部时看不到该提示，行内没有任何失败信息。
3. 检查成功后，行内状态要等整体重新加载才更新，反馈链路依赖额外的网络往返。

## 期望结果

- 每次“立即检查”都在对应依赖行内给出显式结果：更新后的状态快照，或本次检查的原因/错误。
- 未启用、未配置、失败和成功都能被直接看到，不需要滚动到页面顶部寻找提示。
- 不新增页面、不改变检查的实际行为与持久化规则。

## 影响

影响系统状态检查接口的响应结构、系统状态页行内反馈与浏览器 E2E；不改变连通性检查的判定、写入和告警语义。

## 约束

- 每次检查最多产生一个持久化结果（沿用现有 `connectivity` 行为）；未启用能力不写入伪造记录。
- 行内提示只使用服务端返回的真实结果；失败时保留原始错误文本，不包装成成功。
- 页面不得因单行失败而清空其他依赖的状态。

## 非目标

- 不新增检查类型、自动重试或后台轮询。
- 不改变 Provider/浏览器/OSS 检查的实现。
- 不重做系统状态页的其他区块。

## 待确认问题

无。
