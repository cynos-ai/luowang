# v0.7.1 发布复核小修复 Spec

- 状态：实施基线；尚未完成验收或发布
- 目标版本：0.7.1
- [Intent](./intent.md) · [Plan](./plan.md)

## 1. 范围与优先级

本版只修改发布验收检查器、它的自动测试和维护者文档；不修改生产 Run/归档/队列/API 的行为。沿用 [Production Closure Spec](../luowang-v07-production-closure/spec.md) 的 local/live/release 和人工发布边界；清理结论继续按 [单向交接 Spec](../luowang-single-handoff/spec.md) 执行。

本 Spec 补充检查器预检、报告保存和只读复核规则，不取消任何既有发布 AC。跨环境证据复用与按改动缩减未来发布范围仍未实现，不作为本版豁免。

## 2. 检查器契约与反例

### API 输入

- 项目、readiness、queue、runs 与 Run 明细读取保持项目作用域。
- queue/runs 的容器必须是数组；条目及检查器消费的嵌套对象、数组、布尔和文本字段必须满足实际响应类型。不再用 `as LiveRunFact[]` 代替运行时校验。
- 允许无关字段扩展及按生命周期合法缺失的可选字段；不能为 running/interrupted/无归档的历史记录补造完成事实。
- 类型错误输出固定、脱敏的接口/字段类别，不回显响应正文、值或任意动态键名。格式错误只说明无法核验，不自动判定产品实现错误。

### 事实选择与报告

- `reportStatus`、`archiveStatus`、`scenarioStatus`、`progressed` 只读取 `run.archive`；不提供旧扁平形状兼容。
- 普通 passed/failed/blocked/重测事实必须具有适用的已发布正式报告和完成归档；blocked 必须明确 `progressed=false`，并有场景结果和阻塞原因。
- 特殊场景审核 Run 必须满足现有两文件、场景 PR、完成归档、`reportStatus=not_applicable` 契约。它不能代替普通 blocked 事实，也不能进入正式报告 Indexer 请求集合。
- 正式报告请求集合从已选事实产生并去重；普通 Run 未发布或报告 GET 失败仍阻塞，不允许遇到 404 一律跳过。
- 完整 live 校验仍检查截图、清理、Issues、PR、Indexer、GitHub 与 Secret 等现有事实；预检不替代它。

### 回归来源

至少一组测试通过真实生产项目 HTTP 路由与 Run Store 生成响应，再交给检查器解析，防止两份手写 JSON 一起写错。该测试使用临时数据库与合成数据，只是 local 证明。

覆盖 #100–102 对应行为及反例：扁平归档、错误字段类型、缺少归档、错误推进、缺少阻塞原因、普通报告未发布、特殊 Run 不请求报告、普通报告 404 不被忽略。未来修复检查器时应同时补旧错误复现和仍应拒绝的反例；真实 payload 必须脱敏后才能成为 fixture，不能提交原始敏感响应。

## 3. 廉价预检

提供 `npm run test:acceptance:preflight`，复用正式 live 的输入校验、认证、项目归属、readiness 判定和列表解析，不维护另一套判定逻辑。预检读取 `/readiness/status` 缓存；正式 live 继续调用 `/readiness` 实时检查。后者会探测模型并写入/删除 OSS 临时对象，不能因使用 GET 就称其为无副作用。

- 保持既有 live 授权/输入约定；只输出缺失名称，不输出值。
- 允许认证请求建立管理员会话，之后只读取候选项目；不得调用入队、merge、镜像构建、配置写入、模型、OSS 写入或 GitHub 写入。
- 验证项目与目标仓库一致、已有五项 readiness 全部 ok 且有合法检查时间，并验证 queue/runs 响应可解析；尚无 Run 的合法空列表可以预检通过。缓存缺失、需要重检或检查失败时不能通过，不自动发起实时检查。
- 不要求在预检中已有 passed/failed/blocked 事实，不把预检变成正式 live 的重复执行。
- 报告单独使用 `luowang.acceptance-preflight.v1`，包含时间、`status`、缺失项/脱敏原因及成功时的 `readinessCheckedAt`；注明未实时探测依赖，不提供 AC 通过结论，也不写 local/live/release passed。
- 缺输入为 blocked；资源/响应错误为 failed；均非零退出。成功只表示本次预检通过。
- 不自动重建镜像或恢复故障注入；操作者按失败原因修复后新做一次预检。

预检只证明已有就绪记录可读且满足格式/状态要求，不证明现在仍然就绪、首次创建分支前置条件、浏览器实际运行、外部资源联合可用或旧证据适用于新候选。外部镜像被删除而缓存未失效等情况仍由正式实时检查发现。本版不为此新增生产 API。

## 4. 复核与记录保存

### 同一批事实只修检查器

允许在检查器修复通过本地回归后重新运行现有 live 对已完成 Run 的复核，不重新执行模型 Run、不修改原 Run、原报告或上次失败结果；保留既有实时连通性探测的小额模型调用及 OSS 临时对象操作，不能宣称完全无外部副作用。新核验必须输出到新目录。默认时间戳目录保持；显式指定已存在目录时拒绝覆盖，在开始检查前失败。

维护者在现有 Plan/PR 的验收记录写明：候选 commit/镜像 ID、检查器 commit（未提交时标记工作树修改）、项目与 Run/target 引用、差异说明、新旧核验报告位置。不新增长期状态源或通用 manifest。

只读核验结果证明被检查的候选与既有事实，不自动证明后来改动过的产品或其他实例。本版未实现自动候选指纹校验，不得声称有此保证。

### 改动范围判断

- 仅检查器/测试/文档改动：审核差异，补回归，重新核对原证据；不能按提交号变化机械要求模型 Run 全重跑。
- 生产代码、角色资源、运行依赖或配置改变：确认受影响行为，重做相应真实用例，再执行完整 release 复核。
- 换靶场、实例或无法证明证据仍适用：保持 blocked，按现有规则补事实；不自行携带旧证据。
- 减少断言、证据必需改可选、工件适用规则改变或扩大证据沿用范围：负责人确认后才能改。普通字段读取错误可按正常 fix PR 修复。

检查器 PR 应说明原要求、支持修复的原始事实、修改后仍会被拒绝的反例。原因无法确定时明确未知；不能把“驱动错误”转换成产品 passed。
