- 计划：[plan.md](./plan.md)

## 问题

v0.7.0 发布复核连续遇到检查器错误：把 `run.archive` 的字段当顶层读取、选到不足以证明不推进的 blocked Run、为按设计不发布正式报告的特殊 Run 请求报告。#100–102 已修复具体错误，但检查器仍主要依赖手写类型和样例，缺少与真实 API 输出联动的反例验证。重建容器后的执行镜像未就绪也直到正式复核才暴露。

检查器修复、重新核对证据和重新执行模型 Run 的处理规则不够明确，容易造成不必要的重做。README 同时混放项目说明、多个版本历史、启动、升级与验收细节，并仍把已经发布的 v0.7.0 写成候选。

## 期望结果

- 已发生的检查器误报有可重复的本地回归，真实证据缺失仍被拒绝。
- 操作者能在正式复核前发现输入、项目归属、已有就绪记录和响应格式问题，不产生测试 Run 或外部测试副作用；当前依赖是否仍然可用留给正式实时检查。
- 只修检查器时能够重新核对同一批事实，保留原失败记录；不凭检查器修复宣布产品通过。
- README 按读者任务组织，区分已发布版本、开发中版本、部署使用、升级和验收。
- 本版保持小范围；复杂的证据复用、批次绑定和 Git 自动恢复进入后续 Issue。

## 影响与约束

主要影响维护者和发布操作者；不改变罗网角色、正常 Run、归档、目标提交、数据库或产品 API。local/live/release 分离，证据缺失不能通过，历史失败和 tag 不改写，Secret 不进入 Git、日志或报告，测试只连接已授权的非生产资源。发布仍需负责人明确指定版本并授权；获授权后可以由 AI 协助执行发布 PR 合并、新 tag 与发布后核验，不把授权等同于验收通过。

## 非目标

不实现跨靶场/实例/候选的通用证据携带，不引入 Run 清单新协议、自动归因系统、网络重试、自动镜像修复、发布成本看板或工作流引擎；不改变 v0.7.0 历史验收结论，不将旧证据包装成本版已验收。

## 待确认事项

本次小修复范围无阻塞问题。0.7.1 正式发布前仍须确认候选、真实复核资源和发布授权；本任务不预先宣称 live/release 通过。
