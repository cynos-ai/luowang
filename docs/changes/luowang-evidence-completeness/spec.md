# 证据完整性与记录精度 Spec

状态：2026-09-21 经项目负责人批准审核安排。与截图采集完整性共同在 PR #71 实施工程部分；不考虑旧格式兼容，模型行为单独验收。

## 已核实边界

- 填写操作参数确实被省略，填写前登记缺失；自动快照则已有本 Run 文件、统一上传及 Reviewer 读取通道，不能描述为文件必然丢失。
- Cookie 重放已有 command 证据读取；缺的是工具发现与采集、脱敏、读取规则的完整性校验，不能通过放开任意读取解决。
- Harness 已记录操作开始与结束时间，不等同业务事件时间。来源归因的历史重复次数及 intent 中特定计数案例尚缺逐份原文定位，不宣称已复现；Reviewer 指令“三个问题”实际列四项的矛盾已确认。

## A1 填写输入与操作证据

- 复用 screenshot-capture-integrity 的填写前登记及现有 Run Evidence Store，不创建另一套敏感值存储。固定 browser_fill_form、browser_type 在两个 MCP 入口应用同一规则。
- 按固定参数结构校验整批字段后，在调用实际工具前登记文本/选项值。checkbox/radio 的 true/false 作为控件状态保留，不将布尔状态登记成全局敏感文本。空值保留为空；字段名称不用于猜测敏感性。
- 操作证据保留目标、字段类型、名称、脱敏值及本 Run 不可复用的同值标识；type 保留 submit/slowly。返回文字与保存结果使用同一脱敏 owner。页面及截图原像素不变。
- 参数或登记失败阻止实际填写，反馈固定错误并标记证据失败。工具自身失败保留失败结果；批量失败可能已有部分字段执行，输入记录不证明全部填写成功，更不证明网络请求已经发出。
- 文字保护只覆盖登记的完整值及既有脱敏范围，不能恢复被脱敏的原文、识别任意片段或证明模型的否认声明真实。原模型反例不改判。

## A2 导航快照

- 从真实工具结果关联本 Run 的快照文件；校验路径、类型与来源，使用既有 browser evidence 通道。
- 文件正文先复用快照结构解析登记值，再脱敏上传及读取；不直接公开原始 OSS 文本绕过登记。记录文件保存、上传及可读性事实，失败明确可见，不能只留一个无状态的链接。
- 仅接受固定 MCP Snapshot 区块中的 page 时间戳文件名（允许前置 ./），拒绝绝对路径、跨目录、重复区块及其他文件类型。复用 RunWorkspace 的普通文件和 symlink 检查；正文沿用内联解析器的 64 KiB、深度和 YAML 结构限制，不放宽为任意文本。
- 操作记录的 browserSnapshot 保存文件名、sanitized-local 状态、capturedSha256 及 read_browser_evidence 路由；这只证明采集时已保存脱敏正文。上传成功与最终字节哈希以既有 EvidenceReference 为准，读取失败保留既有阻塞。
- 上传前核对采集后的文件哈希，拒绝外部改写；上传时允许依据后来登记的值再次脱敏，所以采集哈希与最终上传哈希分别描述各自阶段。采集失败的文件不得由批量上传绕过；未经过操作关联的自动 page 文件也必须在上传前解析登记，不伪造操作归属。

## A3 证据规则完整性

- 集中维护实际启用工具对应的采集、脱敏及读取规则。明确允许仅保存操作回执的工具及其限制。
- 预检核对实际工具清单，未分类工具报错；运行时再次检查。新增工具不能静默成为“已保存完整证据”，不新增任意工具/文件权限。
- 固定工具规则在 browser/evidence-policy 维护，分类为 replay、filling、snapshot、screenshot、receipt，注明 command 记录与可选 browser/image 工件的读取工具。既有重放/填写处理从同一规则选择，不另维护重复工具集合。
- 连接检查从 MCP 原始清单排除已配置隐藏工具后校验；原生预检检查适配器实际可见清单，同时继续确认危险工具隐藏。运行时在两个代理入口阻止未分类工具，并核对返回的实际工具身份与调用一致。未知名字不回显原始结果，失败进入既有证据失败状态。
- receipt 明确仅保存操作回执；工具原始正文仍按既有规则省略。自动快照、日志和截图只有实际生成并经对应受控通道保存后才是内容证据，不因分类表存在就声称已经保存或可读。

## B 来源、时间与计数

- Reviewer 自身观察与 Runner 陈述分开，引用他人交付须有原文依据；最终 Main 保留 review 的来源及限制。
- 时间标明来源；没有共同时间基准，不从文件名及相对偏移拼出确证事件时间。
- 结构化场景数量由既有结构计算；文字汇总与明细使用一致口径，区分发现数和场景数。先修指令自身矛盾。
- 三项分别设正反案例，独立检查原始 writer 输入及落盘工件，不用自动脱敏或格式通过替代模型准确性。模型预算与冻结案例另行明确，不自动启用历史余额。

## 验收

- AC-EVIDENCE-01：随机、未预登记输入经两个 MCP 入口在实际填写前登记，字段/同值标识及错误可读，跨 Run 隔离； malformed 参数和登记故障不得执行工具。
- AC-EVIDENCE-02：自动快照可追溯至操作，字段登记后脱敏上传，Reviewer 实际读取；异常与缺失如实报告。
- AC-EVIDENCE-03：工具缺规则时预检失败，运行时不静默通过；既有合法证据路由保持。
- AC-EVIDENCE-04：来源、时间、计数分别通过有界模型正反验证；工程与模型结果单列。

自动归档、人工事后审核、历史工件不改及 live/release 边界沿用既有 Spec。
