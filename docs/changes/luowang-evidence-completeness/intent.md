## 问题

### A 族：工具层回避（与已修正的截图护栏同源，3 项）

1. **fill_form 内容省略**：浏览器填写操作只保留时间回执，不记录实际填写的值。若填错字段或填了不该填的内容，执行记录无法复原"实际提交了什么"，审核缺少关键材料。
2. **自动导航快照关联与登记不足**：操作回执省略正文；MCP 已保存快照文件，Harness 也已有统一上传与 Reviewer 读取通道，但操作到文件的关联不明确，文件正文未复用内联快照的字段值登记。不能把现状描述为文件必然丢失。
3. **证据规则缺少完整性检查**：Reviewer 可读类别（command/browser/image）由代码维护，Cookie 重放目前已有 command 读取通道。新增工具与采集、脱敏、读取规则之间缺少完整性预检，容易再次出现内容或可读性缺口。

### B 族：模型记录精度（需独立验证，3 项）

4. **来源归因失实**：把自身观察表述为他人交付（如"Runner 报告识别了 X"而 Runner 未述及）。已有问题反馈，但本次审核尚未定位足以确认重复次数的原始对照，须补原文锚点及定向验证。
5. **时间来源混用**：Harness 已有操作开始/结束时间，但文件生成时间、日志相对偏移与业务事件时间不能直接等同；没有共同基准时，不应拼成确证事件时间。
6. **计数口径不一致**：汇总与明细可能不匹配且未解释口径。已确认 Reviewer 指令写“三个问题”却列四项；原反馈中“4 项确认 + 1 项未验证”的具体模型案例仍须定位原文。

## 期望结果

### A 族（工具层；修法为登记/映射，不省略不回避）

1. fill_form 填写的值按控件结构登记为运行时敏感值；操作记录保留字段与脱敏后内容，不省略正文。
2. 导航快照明确处置：或正文经同源登记脱敏后可读，或如实标注"正文留存于何处、如何访问"；不留无归属暗角。
3. 新增防呆：证据工具产生记录而无类别映射时，**预检直接报错**，不再静默不可读。

### B 族（模型行为；修法为指令 + 定向验证）

4. 自身观察与引用分开：观察明确归属；引用他人交付必须以其原文为据。"模型观察被误写为 Runner 报告"保留为反向测试用例。
5. 时间表述区分"记录时间"与"事件时间"；无时钟基准时不得使用"确证事件时间"类措辞。
6. 汇总数、明细表、口径三者一致；不一致时以明细为准并说明差异。
