# LuoWang v0.7.0 UI 重构 Intent

- 版本：v0.7.0
- 状态：Confirmed
- 日期：2026-09-27
- 基线：v0.6.2

## 1. 当前问题

LuoWang 已经具备多项目、项目隔离、顺序队列、运行准备、历史 Run、场景、报告和全局配置等生产能力，但当前控制台仍沿用功能逐步叠加形成的页面结构：

- 多个不同职责堆在同一张长页面；
- 全局配置、项目配置、就绪检查和运行操作之间的边界不够直观；
- 重要对象缺少稳定 URL，刷新和分享详情依赖页面内状态；
- 当前执行、等待队列、异常和需要人工处理的事项没有形成清楚的操作首页；
- 已上线的多项目事实没有对应的完整页面地图；
- 旧蓝紫暗色后台风格无法形成 LuoWang 自己的产品识别；
- 部分远程 Git 就绪检查可能长时间等待，影响页面可用性。

继续在当前长页面上增加模块，会进一步放大理解成本、状态混淆和维护风险。

## 2. 期望结果

v0.7.0 应形成一套适合单管理员、多项目场景测试工作的完整控制台：

1. 用户能够从工作台快速判断当前执行、等待队列、异常和下一步；
2. 项目列表、项目接入、测试、测试记录、场景、运行准备和设置各自承担明确职责；
3. 全局配置和项目配置在导航、页面标题和提交行为上清楚分离；
4. Run、场景、报告和设置分组拥有可刷新、可分享的稳定 URL；
5. 页面严格展示真实状态，不把保存、连通、就绪、执行中和最终结论混为一谈；
6. 视觉上采用唯一的“怪盗动态构成”方向，形成黑、报纸白和行动红的 LuoWang 识别；
7. 倾斜、切角和错位可以进入内容与控件，同时保持文字、焦点和操作完整可用；
8. 桌面和 Pad 范围内具备稳定的响应式、键盘和缩放体验；
9. 不改变现有安全边界、项目隔离和 Run 状态机。

## 3. 受影响的人和系统

### 3.1 操作者

唯一管理员将使用新的页面地图完成项目接入、运行准备、测试发起、实时观察、历史审核和配置管理。

### 3.2 Web 控制台

现有多项目控制台的导航、路由、页面组织、视觉组件、状态加载和浏览器测试需要重构。

### 3.3 HTTP API

现有项目级 API 继续作为事实 owner。为工作台、系统状态和稳定详情页，可以增加对现有事实的只读聚合，但不能借此增加新的测试能力。

### 3.4 后端运行边界

Git 远程就绪检查需要有界结束。队列、Run、归档、场景、Evidence、Secret 和配置的既有所有权不改变。

## 4. 约束

- 以 v0.6.2 已发布能力为基线；
- 单管理员、全局串行执行保持不变；
- 项目和 Secret 必须继续按 projectId 隔离；
- 所有测试环境必须为非生产环境；
- `passed / failed / blocked / interrupted` 必须严格区分；
- 清理失败单独告警，不改写功能结论；
- 保存配置不等于连通或就绪；
- Git、场景、报告和 Run 的事实来源不改变；
- 页面不得展示 Secret、思维链、未经脱敏的命令或环境响应；
- 主设计宽度为 1440px，最低支持 768 CSS px；
- 支持键盘、可见焦点、200% 缩放和 reduced motion；
- 重要对象使用真实页面，弹框只用于短确认；
- 不复制第三方角色、Logo、字体、图形资产或具体界面。

## 5. 非目标

本次重构不包含：

- 多用户、组织、权限或租户；
- 跨项目并行 Run；
- 取消、重排或优先级编辑；
- 在线编辑或删除场景；
- 人工测试套件；
- 通知中心、全局搜索或命令面板；
- 独立报告中心或证据中心；
- 项目级模型、浏览器或 OSS 覆盖；
- 永久删除项目和清空历史；
- 移动端；
- 主题切换或暗色主题；
- #93 Git HTTPS 受控代理；
- #95 模型质量对照重跑；
- 其他新的产品状态或能力。

## 6. 成功表现

重构完成后，操作者不需要理解旧页面的模块堆叠即可完成主要任务；任何重要状态都能追溯到真实项目、Run、commit、报告或检查事实；页面在指定宽度和辅助输入下保持可读、可操作；视觉表达具有明确产品识别，但不会牺牲状态判断和长期使用。

## 7. 待确认问题

当前没有阻塞实施计划的问题。实现过程中如发现必须改变页面归属、产品状态、安全边界或数据所有权，应停止对应阶段，先更新 Intent/Spec 并由项目负责人确认。
