# LuoWang v0.7.0 视觉与交互设计

- 版本：v0.7.0
- 状态：全页面设计与状态样例已完成；生产实现尚未开始
- 日期：2026-09-27
- 依赖规格：`spec.md`
- 选定方向：怪盗动态构成
- 原型入口：`prototypes/luowang-v07-design.html`

## 1. 文档职责

本文定义 v0.7.0 控制台的视觉语言、设计 token、构图规则、组件表现、响应式行为和视觉验收标准。

`spec.md` 继续负责页面地图、产品行为、状态语义、安全边界和内容归属。发生冲突时：

1. 产品事实、安全和页面归属以 `spec.md` 为准；
2. 颜色、字体、空间、构图和组件外观以本文为准；
3. 原型用于验证本文，不得用原型样例数据覆盖真实产品规则。

## 2. 设计决定

v0.7.0 采用唯一视觉方向“怪盗动态构成”。不再保留其他候选方向，也不提供主题切换。

它使用黑、报纸白和高纯度红形成强烈信息层级，通过斜向色块、错位边框、动态切角和不完全对齐制造行动感。它不是传统后台卡片墙，也不是只给水平布局换一套颜色。

本方向只吸收怪盗漫画式的构图方法，不复制任何第三方角色、标识、字体、图形资产或具体界面。产品标识只使用“罗网 LuoWang”文字。

## 3. 核心原则

### 3.1 事实先于装饰

视觉强度必须帮助用户更快识别：

1. 当前需要处理的事项；
2. 正在执行的任务；
3. 当前状态与结论；
4. 下一步可执行操作；
5. 项目和全局作用域。

不为填补空白增加统计卡片、图表、口号或假数据。

### 3.2 动态构图不等于强制水平

标题、正文、状态、表格、表单、按钮和阶段块都可以倾斜、旋转、错位或进入斜向构图。禁止的不是变形，而是变形造成的不可读和不可操作。

每次变形必须同时满足：

- 文字完整位于所属视觉边界和安全内边距内；
- 字号、行高和行宽适合实际内容；
- 不与切角、边框、装饰色块或相邻内容碰撞；
- 阅读顺序明确，DOM 顺序不因视觉错位而改变；
- 键盘焦点框、点击区域和视觉位置一致；
- 长中文、英文 ID、commit 和 digest 可以完整换行或安全截断；
- 1440px、1024px、768px 和 200% 缩放下不丢失内容或操作。

不能以“全部恢复水平”作为解决溢出的默认方法。应优先调整安全区、内边距、字号、行高、换行和构图关系。

### 3.3 一个区域有一个主阅读轴

页面可以同时存在多个倾斜角度，但每个信息区域应有可识别的主阅读轴。装饰层不能改变正文的语义顺序，也不能让用户在同一段内容中反复切换阅读方向。

### 3.4 作用域可见

- 全局页持续显示当前为全局作用域；
- 项目页持续显示项目名称和 `owner/repository`；
- 项目上下文使用独立黑色带状区域，与全局导航明显分层；
- 写操作确认框再次显示项目和仓库；
- 红色只强调行动、异常和当前重点，不用于伪造项目状态。

## 4. 色彩系统

### 4.1 核心色

| Token | 色值 | 用途 |
| --- | --- | --- |
| `color.black` | `#070707` | 主文字、顶栏、强边框、深色信息面 |
| `color.paper` | `#FFFDF4` | 主画布、表单和内容面 |
| `color.action` | `#E51C23` | 主操作、当前阶段、异常重点和构图色块 |
| `color.gray` | `#85857F` | 纸白背景上的次要文字 |
| `color.line` | `#B7B5AB` | 分隔线和次级边框 |

行动红使用 `#E51C23`，而不是更亮但不适合承载小号白字的装饰红。小号白字只能放在通过对比度检查的红色或黑色背景上。

### 4.2 语义色

| Token | 色值 | 语义 |
| --- | --- | --- |
| `color.success` | `#286956` | passed、已通过、已完成 |
| `color.warning` | `#A8660F` | blocked、等待人工处理、陈旧 |
| `color.danger` | `#E51C23` | failed、连接失败、高风险操作 |
| `color.focus` | `#E51C23` | 键盘焦点 |

状态不能只靠颜色表达。状态文字、图形轮廓或标签必须同时存在。

### 4.3 色彩比例

默认页面以纸白为主，黑色建立结构，红色制造重点：

- 纸白约占主内容面积的 65%–80%；
- 黑色用于全局框架、标题带、边框和关键状态区；
- 红色只占主要视觉面积的 10%–20%；
- 同一视口中不把所有面板都设为红色或黑色。

比例是构图基准，不是机械配额。错误、运行中任务和确认操作可以提高红色占比。

## 5. 字体与文字

### 5.1 字体角色

```css
--font-display: "Nimbus Sans Narrow", "Noto Sans CJK SC", sans-serif;
--font-body: "Noto Sans CJK SC", sans-serif;
--font-mono: "JetBrains Mono", "JetBrainsMono Nerd Font", monospace;
```

- 展示字体：页面标题、核心结论、主要区块标题；
- 正文字体：操作说明、表单、列表和报告内容；
- 等宽字体：时间、Run ID、commit、digest、路径和技术标识。

实现时必须确认字体资源可用；缺失时使用上述回退，不允许因字体未加载造成标题溢出。

### 5.2 字号基准

| 层级 | 建议尺寸 | 规则 |
| --- | --- | --- |
| 页面主标题 | `clamp(46px, 6vw, 86px)` | 可倾斜；必须完整进入标题安全区 |
| 核心运行标题 | `clamp(36px, 4.2vw, 62px)` | 允许两行，禁止遮挡状态 |
| 结论 | `clamp(54px, 7vw, 92px)` | passed/failed/blocked 必须含文字 |
| 区块标题 | 24–30px | 高字重，保持短句 |
| 正文和操作 | 14–16px | 默认行高不低于 1.45 |
| 表格和列表 | 12–14px | 主要事实不得低于 12px |
| 技术元数据 | 11–12px | 仅用于短时间、ID 和摘要 |

10px 只能用于原型标记或极短辅助标签，不用于生产正文、错误信息和必要操作说明。

### 5.3 排版规则

- 中文标题允许自然换行，不以缩小到不可读作为适配手段；
- 英文标识使用 `overflow-wrap: anywhere` 或明确的中间省略；
- 正文不使用全大写；
- 技术标识可以保留准确英文；
- 页面标题可以压缩字距，正文不能；
- 斜向文字的实际基线必须清晰，不能只为装饰连续旋转多行正文。

## 6. 空间、网格与几何

### 6.1 基础尺寸

- 基础空间单位：4px；
- 主画布：1440px；
- 内容最大宽度：1580px；
- 桌面页面边距：42px；
- 面板间距：20px；
- 面板默认内边距：26px；
- 表单控件最低高度：42px；
- 普通点击目标不得小于 40×40px；
- 强边框：4–5px；
- 次级边框：1–2px。

### 6.2 网格

主内容使用 12 列网格。工作台默认关系为：

- 需要处理：3 列；
- 当前执行：6 列；
- 等待队列：3 列；
- 项目状态：7 列；
- 最近完成：5 列。

实际实现可根据内容调整列宽，但必须保持当前任务为首屏最大信息面。

### 6.3 角度与切角

原型的默认起点：

- 大型标题或装饰色块：约 7–13°；
- 主要容器：约 -1.5–1.5°；
- 标签、状态、阶段和按钮：约 -2–2°；
- 切角深度：10–14px。

这些数值不是风格上限。需要更强角度时可以使用，但必须通过实际长文本、焦点框和响应式验收。

切角组件的内容安全内边距不得小于：

```text
max(12px, 切角深度 + 8px)
```

不得把文字直接放在会裁掉其边界的 `clip-path` 区域内。

## 7. 全局框架

### 7.1 产品顶栏

- 高度约 94px；
- 纸白底与红色斜向大色块形成全局结构；
- “罗网 LuoWang”文字标识放在黑色不规则块中；
- 顶层导航位于红白交界区域；
- 当前导航使用黑底白字，并保留可见焦点；
- “需要处理”数量和管理员入口位于右侧。

顶栏色块可以越过普通列线，但不能遮挡导航文字。

### 7.2 项目上下文栏

- 使用黑色横向信息带；
- 红色斜块区分项目导航；
- 左侧显示项目名称和仓库；
- 右侧显示项目状态与项目内导航；
- 当前项目页使用纸白底黑字标签；
- 所有项目导航在黑色和红色区域上都必须保持足够对比度。

### 7.3 页面标题

- 黑色不规则标题面承载白色大标题；
- 红色块可以压叠在标题面边缘，但不能覆盖文字；
- 作用域标签位于标题上方，并与标题保持可计算间距；
- 页面说明只在说明后果、范围或当前事实时出现；
- 右侧事实说明可以轻微反向倾斜，形成视觉对位。

## 8. 组件规范

### 8.1 面板

- 默认使用纸白底、4px 黑边和动态切角；
- 重要面板可以增加 7–9px 黑色错位阴影；
- 面板可整体轻微旋转；
- 相邻面板使用不同但协调的角度；
- 面板旋转后必须预留外部间距，不能压住相邻操作。

工作台的语义面：

- 需要处理：红底白字；
- 当前执行：纸白主体加黑色标题面；
- 等待队列：黑底白字；
- 项目状态和最近完成：纸白信息面。

### 8.2 状态标签

- 黑底白字或语义色边框；
- 使用短中文状态；
- 可使用 1–2° 轻微倾斜；
- `passed / failed / blocked / interrupted` 不得合并；
- 执行中状态不得伪装成最终结论；
- 陈旧数据必须同时显示原因和最后成功时间。

### 8.3 阶段条

八个运行阶段使用独立块：

```text
排队 → 准备目标 → Main 规划 → Runner 执行
→ Reviewer 审核 → Final Main 汇总 → 数据清理 → 归档与索引
```

- 奇偶阶段可以上下错位并采用不同轻微角度；
- 当前阶段使用行动红；
- 已完成、失败、未运行均有文字；
- 768px 下变为四列两行；
- 不使用虚假百分比。

### 8.4 按钮

- 主操作：行动红底、白字、黑色强边和错位阴影；
- 次要操作：纸白底、黑色边框；
- 高风险操作：行动红，但必须附带具体动作名称；
- 可以使用斜边和轻微旋转；
- hover 不能是唯一状态；
- disabled 必须同时降低对比并禁止交互；
- focus-visible 使用 2px 行动红外轮廓，偏移 3px。

### 8.5 表格和列表

- 表头使用黑底白字；
- 表头单元可产生轻微高低错位；
- 数据行保持稳定扫描顺序；
- 状态标签可以倾斜，数值和长标识保持可复制；
- 768px 下优先保留主要列，次要内容进入展开区域或局部横向滚动；
- 不允许整页产生横向滚动。

### 8.6 表单

- 表单可以整体轻微倾斜，字段仍按明确列线组织；
- 分组标题使用黑底白字标签；
- 输入文字、placeholder 和错误信息必须完整位于输入框内；
- 字段错误不能只改变边框颜色；
- Secret 不回显原值；
- 保存成功与连接检查通过必须使用不同反馈。

### 8.7 确认弹框

- 纸白主体、黑色强边、红色侧边与错位阴影；
- 整体可以轻微旋转；
- 标题使用黑底白字动态块；
- 必须显示项目、仓库、来源、请求和后果；
- 操作按钮位于稳定的右下区域；
- 打开后锁定焦点，关闭后归还触发点；
- 点击背景关闭只用于无输入的普通确认。

### 8.8 证据

正式实现中的证据组件使用同一视觉语言，但不能为了构图裁剪证据本身：

- 缩略图保留原始比例；
- 完整性状态显示文字和图形；
- 缺失、读取失败、外部存储不可达分开表达；
- 截图不得因装饰性遮罩隐藏待验证内容；
- 大图页面或弹层必须提供完整查看能力。

## 9. 页面应用

### 9.1 工作台

首屏按“需要处理—当前执行—等待队列”建立从左到右的行动轴。当前执行是最大面板，标题和阶段条可以采用不同角度；项目状态和最近完成在下方形成稳定信息基座。

### 9.2 测试

运行中的测试以当前阶段和当前场景为主体。八阶段条允许错位构图；右侧“本次测试”和“运行准备”保持较稳定，作为信息锚点。

idle、queued 和 completed 状态沿用同一视觉层级，不新增并列主操作。

### 9.3 测试记录详情

正式结论使用大字号和独立斜向结果块。摘要、场景结果、审核、正式报告、证据和技术信息保持稳定标签顺序。装饰不能改变报告正文和证据的阅读顺序。

### 9.4 全局设置与项目设置

侧栏和表单允许采用不同微小角度。表单字段保持清楚的两列或单列结构，分组标题负责视觉变化。设置页不能因视觉表达弱化作用域、锁定状态或保存后果。

### 9.5 系统状态

系统状态是产品中的只读诊断页。原型下拉中的“设计规范”仅用于展示视觉 token，不代表系统状态的最终页面内容。实现系统状态时必须使用 `spec.md` 第 10 节的真实服务、依赖和资源事实。

### 9.6 其他页面

登录、项目列表、接入向导、项目概览、测试记录列表、场景、运行准备、账号设置和项目设置均使用本文的同一框架与组件语法，不为单页创建另一套视觉主题。

## 10. 加载、空、错误、陈旧与锁定

- 加载：使用结构骨架，不模拟测试结果和数字；
- 空状态：保留页面标题和下一步操作，不保留无意义空卡片；
- 局部错误：在所属面板内显示事实、时间和重试；
- 全页错误：只用于全局公共依赖导致页面无法成立；
- 陈旧缓存：继续显示最后可信内容，同时显示陈旧原因和时间；
- 锁定：显示导致锁定的具体测试记录与入口；
- 保存失败：保留用户输入。

这些状态可以使用红黑强构图，但不能让所有异常都看起来相同。

## 11. 动效

- 默认反馈时长：120–160ms；
- 选定原型基准：140ms；
- 页面进入不使用大面积连续动画；
- 导航、状态和重点色块可以沿斜向阅读轴短促切入；
- 动画不能造成布局跳动、焦点漂移或点击区域变化；
- 实时刷新不抢焦点、不重置滚动位置；
- `prefers-reduced-motion: reduce` 下取消非必要位移、旋转过渡和循环动画。

## 12. 响应式规则

### 12.1 1440px

完整展示 12 列构图、侧栏、错位面板和主要旋转关系。这是主要设计与截图基准。

### 12.2 1024px

- 顶栏隐藏非必要元信息；
- 测试和记录详情右侧信息下移；
- 设置侧栏缩窄；
- 保留主要斜向构图。

### 12.3 768–820px

- 工作台面板改为单列；
- 测试侧栏和设置表单改为单列；
- 阶段条改为四列；
- 大型面板取消会造成相互覆盖的整体旋转；
- 内部标题、状态、阶段、按钮和切角继续保留动态语言；
- 页面内容不得产生横向溢出。

取消大型容器旋转是空间安全处理，不表示 Pad 版本切换成另一套水平主题。

### 12.4 低于 768px

本版不承诺移动端可用，但实现不能影响桌面浏览器在 200% 缩放、有效宽度仍满足最低要求时的访问。

## 13. 可访问性

- DOM 顺序必须符合阅读顺序，不能用视觉错位重排语义；
- 全部操作支持键盘；
- 焦点轮廓不被 `overflow` 或 `clip-path` 裁切；
- 状态不只依赖颜色；
- 正文和必要控件达到 WCAG AA 对比度；
- 大标题和装饰文字不能替代可访问名称；
- 表格使用真实表头；
- 表单标签与输入关联；
- 弹框具备名称、焦点锁定和焦点归还；
- 证据图片具备可读名称和必要替代文本；
- 200% 缩放不丢失内容或操作。

## 14. 文案规则

沿用 `spec.md` 的产品术语：

- 使用“测试记录”，不用 `Runs` 作为导航名称；
- `Runner` 只指执行场景的 Agent 角色；
- `Run ID` 只用于技术标识；
- 使用“工作台、项目、系统状态、设置”；
- 全局页面标题使用“全局设置”；
- 不使用营销口号、装饰性英文眉题和重复解释标题的说明；
- 错误文案说明事实、影响和下一步；
- 设计样例必须明确标记，不能冒充真实运行。

## 15. 实现约束

- 设计 token 应集中定义，不在组件内复制色值和角度；
- 视觉变形应通过可复用变体实现，不为每个页面写孤立定位；
- 组件在变形前先完成正常文档流布局；
- 使用 `clip-path` 时必须为内容保留安全区；
- 不通过固定高度隐藏长文本；
- 不通过 `overflow: hidden` 掩盖标题、焦点框或错误信息；
- 旋转后的交互元素必须保持视觉位置与实际命中区域一致；
- 真实页面和稳定 URL 规则不因视觉实现改变；
- 不引入主题切换、暗色模式或第三套视觉语言。

建议的核心 token：

```css
:root {
  --lw-black: #070707;
  --lw-paper: #fffdf4;
  --lw-red: #e51c23;
  --lw-gray: #85857f;
  --lw-line: #b7b5ab;
  --lw-success: #286956;
  --lw-warning: #a8660f;
  --lw-space: 4px;
  --lw-page-pad: 42px;
  --lw-panel-gap: 20px;
  --lw-panel-pad: 26px;
  --lw-motion-fast: 140ms;
}
```

## 16. 验收标准

### 16.1 视觉

- 所有页面使用怪盗动态构成，不出现旧候选主题；
- 红黑纸白层级清楚，红色不过量；
- 页面标题、主要状态和唯一主操作可以快速识别；
- 不退化为普通卡片后台；
- 不复制第三方受保护视觉资产。

### 16.2 可读性

- 长中文、英文 ID、commit、digest 和错误信息不越界；
- 变形文字完整位于所属框体内；
- 表格、表单和阶段条没有文字碰撞；
- 1440px、1024px、768px 无整页横向溢出；
- 200% 缩放不丢失主要内容和操作。

### 16.3 交互与状态

- 键盘可以完成全部操作；
- 焦点始终可见；
- 点击区域与视觉位置一致；
- passed、failed、blocked、interrupted 和 running 均有非颜色表达；
- 保存、连通和就绪不会显示成同一状态；
- 弹框锁定并正确归还焦点；
- reduced motion 生效。

### 16.4 内容真实性

- 空数据库不显示样例项目和统计；
- 原型样例数据不进入生产默认值；
- 系统状态、测试结论、清理、归档和证据状态来自真实事实；
- AI 审核不显示为人工评分；
- 清理失败不改写功能结论。
