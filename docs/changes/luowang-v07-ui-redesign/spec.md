# LuoWang v0.7.0 页面内容设计

- 版本：v0.7.0
- 状态：页面内容、信息架构和视觉设计已确认；实现尚未开始
- 日期：2026-09-27
- 基线：v0.6.2

## 1. 目标

v0.7.0 重做 LuoWang 控制台的信息架构、页面内容和视觉交互。它不是给现有长页面换色，而是在已上线的多项目能力之上重新组织操作路径。

本文件只确定：

- 有哪些页面；
- 每个页面放什么；
- 页面之间如何进入和切换；
- 全局配置与项目配置如何区分；
- 状态、错误、陈旧数据和危险操作如何表达；
- 后续视觉设计必须遵守的内容边界。

本文件不确定颜色、字体、圆角、阴影、动效或具体组件外观。已确认的视觉方向和组件规则记录在同目录 `design.md`。

## 2. 版本边界

### 2.1 本版包含

- 全新的全局导航与项目内导航；
- 工作台、项目列表、项目接入、系统状态、全局设置和账号设置；
- 项目概览、测试、测试记录、场景、运行准备和项目设置；
- 重要对象的稳定 URL 和深链接；
- 对现有事实进行必要的只读聚合；
- 现有运行阶段、证据、报告、场景和归档状态的结构化展示；
- 新界面需要的加载、空、错误、陈旧和锁定状态；
- 不改变产品行为的缺陷修复，包括 #94 Git 远程检查缺少有界超时。

### 2.2 本版不包含

- 取消或中止测试；
- 多用户、组织、角色和权限；
- 跨项目并行测试；
- 项目级模型、浏览器或 OSS 覆盖；
- 在线编辑或删除场景；
- 人工测试套件；
- 全局搜索或命令面板；
- 通知中心和已读/未读状态；
- 罗网内的 GitHub Issue/PR 管理器；
- 独立报告中心或证据中心；
- 模型成本或管理驾驶舱；
- #93 受控 Git HTTPS 代理配置；
- #95 模型质量对照重跑；
- 其他新的产品行为。

API 调整只能用于展示现有能力、建立稳定路由和聚合现有事实，不能借 UI 重构扩大产品范围。

## 3. 内容原则

### 3.1 操作优先

工作台先显示需要处理的事项、当前执行和等待队列，不以通过率、趋势图或装饰性指标占据首屏。

项目概览只回答：

1. 项目现在能不能测试；
2. 最近一次测试结果是什么；
3. 下一步应该做什么。

### 3.2 真实事实优先

- `blocked`、`failed`、`interrupted` 和 `passed` 必须严格区分；
- 保存配置不等于连接成功或项目就绪；
- 实时进度不是最终结论；
- 清理失败单独告警，不改写已经成立的测试结论；
- 没有数据时不填入示例项目、模拟 Run 或虚构统计；
- 缓存陈旧时继续展示最后可信数据，并同时显示陈旧原因和最后成功时间。

### 3.3 不使用解释性 AI 文案

禁止：

- 营销口号；
- 装饰性英文眉题；
- 标题下重复解释标题的段落；
- “全面掌控测试流程”“轻松提升效率”等泛化描述；
- 为填补空白而增加理念、假数据或无操作价值的提示。

页面直接使用真实产品语言：

- 页面：`工作台`、`测试记录`、`运行准备`；
- 区块：`需要处理`、`当前执行`、`等待队列`；
- 操作：`发起测试`、`重新检查`、`准备镜像`；
- 事实：`Git 远程检查超时`、`3 个请求正在等待`。

只有安全边界、不可逆后果、首次使用、错误、空状态和容易误解的字段可以附加说明。帮助文字必须说明后果或下一步，不能重复字段名。

### 3.4 作用域始终可见

- 全局设置持续标记“全局设置 · 影响全部项目”；
- 项目页持续显示项目名称和 `owner/repository`；
- 项目写操作和确认框再次显示项目名称与仓库；
- projectId 是服务端归属，不从显示名称或前端选择推导；
- 切换项目后，旧项目的迟到响应不能覆盖新项目页面。

- GitHub Issue/PR；
- 通知；

## 5. 全局框架与导航

### 5.1 全局框架

所有登录后页面共享：

- 产品标识；
- 顶层导航；
- 全局需要处理数量；
- 当前管理员入口；
- 当前页面作用域；
- 必要的服务不可用提示。

不设置通知铃铛。“需要处理”数量链接到工作台，问题只有在真实状态恢复后消失，不能通过“标记已读”隐藏。

### 5.2 项目上下文栏

进入项目后持续显示：

- 项目显示名称；
- `owner/repository`；
- 可运行、暂停或未就绪；
- 项目切换器；
- 项目内导航。

项目切换规则：

- 列表页切换后保留同级页面；
- 测试记录详情切换后进入新项目的测试记录列表；
- 场景详情切换后进入新项目的场景列表；
- 有未保存修改时先确认；
- 写操作提交中禁止切换；
- 详情 ID 不得跨项目复用。

## 6. 登录

### 6.1 页面目的

完成现有单管理员认证，不承担产品介绍或管理员初始化。

### 6.2 页面内容

- LuoWang 真实产品标识；
- 管理员密码；
- 登录；
- 安全、连接或服务不可用提示；
- 页面底部的当前版本。

### 6.3 状态

- 提交中防止重复登录；
- 失败使用统一安全提示，不暴露账号是否存在；
- 服务未通过安全初始化时显示部署操作提示，但不提供网页设密入口。

### 6.4 不放什么

- 注册；
- 默认密码；
- 匿名设置管理员密码；
- 邮件找回密码；
- 产品营销内容；
- 虚构运行状态。

## 7. 工作台

### 7.1 页面目的

登录默认首页。跨项目回答“现在发生什么”和“我需要处理什么”。

### 7.2 内容顺序

#### 需要处理

- 项目未就绪；
- 项目凭据或共享依赖异常；
- Git、镜像或测试环境失败；
- blocked 测试；
- 清理、归档或同步告警；
- 陈旧缓存；
- 待人工审核的场景 PR。

每条事项包含项目、事实、发生时间和正确入口。不能在这里复制完整详情。

#### 当前执行

- 项目；
- 测试记录 ID；
- 当前阶段和角色；
- 当前场景；
- 开始时间和已持续时间；
- 最后更新时间；
- 进入项目“测试”页。

没有当前执行时显示简短真实空状态，不保留空卡片。

#### 等待队列

- 跨项目实际顺序；
- 项目和请求；
- 创建时间；
- 等待原因；
- 暂停项目中保留的请求。

不提供本版不存在的取消、重排或优先级编辑。

#### 项目状态

每个项目只显示：

- 可运行、暂停或未就绪；
- 当前执行或排队状态；
- 最近一次测试结论；
- 待处理数量；
- 最近同步状态。

#### 最近完成

显示最近若干次测试的项目、结论、固定提交、完成时间和正式报告状态。

### 7.3 首次使用状态

零项目时，工作台显示：

```text
1. 完成全局设置
2. 检查系统状态
3. 连接第一个项目
```

每一步使用真实状态和入口。不创建强制导览；全局条件未齐时仍可连接项目，但项目保持暂停和未就绪。

### 7.4 不放什么

- 通过率大图；
- 趋势图；
- 模型成本；
- 无决策价值的总数卡片；
- 跨项目混合的场景或报告列表。

## 8. 项目列表

### 8.1 页面目的

比较和管理多个项目，并进入项目工作区。

### 8.2 列表字段

- 项目名称；
- 仓库；
- 可运行、暂停或未就绪；
- 当前执行或排队状态；
- 最近测试结论；
- 就绪问题数量；
- 最近同步时间和陈旧标记；
- 需要处理的告警；
- 进入项目。

### 8.3 排序与筛选

默认排序：

1. 需要人工处理；
2. 正在执行；
3. 正在排队；
4. 正常项目；
5. 已暂停项目。

支持现有数据可直接完成的名称、仓库和状态筛选。可切换按名称或最近活动排序。

### 8.4 操作

- 页面主操作：`连接新项目`；
- 行内主操作：进入项目；
- 暂停、恢复等低频操作进入行末菜单；
- 不提供永久删除项目或历史清除。

## 9. 新项目接入

### 9.1 页面形式

使用独立 URL 的全页面、可恢复向导，不使用弹窗。

### 9.2 步骤

#### 1. 连接仓库

- 项目显示名称；
- GitHub 仓库地址；
- 私有仓库所需 Token；
- 核验稳定仓库 ID、owner/name 和重复接入。

只有仓库身份验证成功后才创建项目。创建后项目立即以 `paused` 保存；Token 进入项目 Secret Store，不保留在表单中。

#### 2. 配置测试

- 场景分支；
- 场景维护模式；
- 固定包含标签；
- 生成语言；
- 执行 Dockerfile。

默认值只是初始配置，不能表示已经检查通过。

#### 3. 配置环境

- 非生产环境确认；
- 环境说明；
- 服务地址；
- 测试账号和密码；
- 清理配置和 Token；
- 必填、可选和暂不配置状态。

#### 4. 准备并启用

按真实顺序：

1. 同步仓库；
2. 准备执行镜像；
3. 检查环境和共享依赖；
4. 展示完整就绪结果；
5. 用户明确启用项目。

全部检查通过后也不能自动启用或自动发起测试。

### 9.3 中断与恢复

- 第一步完成后可以随时退出；
- 项目列表显示接入未完成；
- 再次进入时从缺失步骤继续；
- 已保存 Secret 不重新展示；
- 返回修改时说明是否需要重新同步、检查或准备镜像；
- 失败保留已完成步骤，不要求从头开始。

## 10. 系统状态

### 10.1 页面目的

展示全局只读运行事实，定位影响多个项目的共同故障。它不承担配置编辑和完整日志查看。

### 10.2 服务

- LuoWang 版本和构建；
- 数据库状态；
- 主密钥或 Secret Store 可用状态；
- 调度器状态；
- 最近检查时间。

当前没有持久化服务启动时间，本版不展示。

### 10.3 共享依赖

- 模型 Provider；
- 浏览器运行环境；
- OSS；
- 正常、异常、未配置或检查超时；
- 最后成功时间（仅在已有真实数据时）；
- 脱敏失败原因；
- 对应全局设置入口。

### 10.4 执行资源

- 当前可确认归属的项目容器；
- 项目执行镜像；
- `referenced / restart-candidate / manual-review` 等现有盘点结论的可读表达；
- 候选可回收体积只作为盘点，不承诺 Docker 实际可回收同等空间；
- 无法确认归属时停止展示清理预览并报告错误。

资源盘点保持只读，不提供一键删除容器、镜像、卷或数据库。

### 10.5 恢复信息

提供现有恢复说明入口。当前没有持久化恢复演练历史，本版不展示虚假“最近演练”。

### 10.6 不放什么

- 原始日志流；
- Agent 对话；
- 环境变量；
- Secret 或带凭据 URL；
- 与诊断无关的大量指标。

## 11. 全局设置

### 11.1 页面共同规则

页面持续显示：

```text
全局设置 · 影响全部项目
```

- 每个分组独立保存；
- Secret 与普通配置分开提交；
- 保存成功不等于连接检查通过；
- 有准备中或运行中任务导致锁定时，显示具体测试记录；
- 不提供项目级模型、浏览器或 OSS 覆盖。

### 11.2 模型与角色

- Provider；
- Provider Base URL；
- Main、Runner、Reviewer 模型；
- 已有 thinking 等角色配置；
- Final Main 复用关系的事实说明；
- 修改前显示影响全部项目。

### 11.3 浏览器

- 启用状态；
- Chromium、Firefox 或 WebKit；
- headless；
- 现有超时配置；
- 最近可用状态入口。

### 11.4 对象存储

- Endpoint；
- Region；
- Bucket；
- Public URL；
- access mode；
- object prefix；
- 连接检查状态。

已有历史证据时，必须阻止会使旧地址失效的原位修改，并说明原因。

### 11.5 本地数据

- 受控仓库和报告目录只读展示；
- 保留天数；
- 可确认的占用和清理状态；
- 不允许输入任意跨项目本机路径。

### 11.6 全局凭据

- Provider API Key；
- OSS Access Key ID；
- OSS Access Key Secret；
- 已配置/未配置和安全掩码；
- 更新、轮换和清除分别确认；
- 不出现项目 GitHub Token、测试账号或清理 Token。

## 12. 账号设置

### 12.1 页面内容

- 管理员显示名称；
- 当前密码；
- 新密码；
- 确认新密码；
- 明确的密码要求；
- 退出当前会话。

### 12.2 不放什么

- 头像；
- 邮箱；
- 主题偏好；
- 通知偏好；
- 多设备会话管理；
- 角色权限；
- 系统版本和部署信息。

## 13. 项目概览

### 13.1 页面目的

提供项目判断和正确入口，不复制其他页面的完整内容。

### 13.2 页面内容

- 项目名称、仓库和状态；
- 当前最重要的下一步；
- 当前或最近一次测试摘要；
- 运行准备摘要；
- 场景数量；
- 最近同步时间和固定提交；
- 基于现有持久事实整理的最近活动。

### 13.3 推荐行动

只显示一个主行动：

- 可运行：`发起测试`；
- 未就绪：`完成运行准备`；
- 有测试执行中：`查看当前执行`；
- 有 blocked 或归档失败：`处理问题`。

`发起测试`进入测试页并带入项目上下文，不在概览一键启动。

### 13.4 不放什么

- 项目设置表单；
- Secret 输入；
- 完整 Run 列表；
- 完整场景列表；
- 多个同等主按钮；
- 装饰性统计图。

## 14. 测试

### 14.1 页面目的

使用一个自适应页面承载项目的当前测试任务。页面随 `idle → queued → running → completed` 改变主要内容，每次只突出一个当前任务。

### 14.2 空闲

提供已有的两类请求：

- 测试当前场景分支；
- 纳入已确认的来源分支、tag 或 commit 后测试。

按请求类型显示：

- 测试要求文本；
- 来源 ref；
- 首次初始化；
- 把来源纳入当前项目场景测试分支的明确确认；
- 当前项目、环境、场景分支和运行准备摘要。

未就绪时禁止提交，并直接列出缺失条件。页面不能要求用户决定 Main 应自行判断的浏览器执行语义。

### 14.3 排队

- 队列位置；
- 前方当前执行项目；
- 请求类型和来源；
- 创建时间；
- 等待原因；
- 已固定的配置修订等现有上下文。

不显示虚假完成百分比，不提供取消或重排。

### 14.4 执行中

阶段使用现有 Run 生命周期和活动事实：

```text
排队
准备目标
Main 规划
Runner 执行
Reviewer 审核
Final Main 汇总
数据清理
归档与索引
```

每个阶段只显示未开始、进行中、已完成、失败或未运行。页面同时显示：

- 当前角色；
- 当前场景；
- 已完成场景数和总数；
- 开始时间和真实耗时；
- 最后更新时间；
- 脱敏活动摘要；
- 阻塞原因；
- 进入完整测试记录详情。

不展示模型思维链、完整 Prompt、Secret、带凭据 URL 或原始环境响应。

### 14.5 刚完成

显示简洁结论、场景结果摘要和正式测试记录入口。重新测试重新进入空闲表单，不在结果区直接重复提交。

## 15. 测试记录

### 15.1 术语

产品界面统一使用“测试记录”。

- 一条测试记录对应一次完整 Run；
- `Run ID` 只用于 ID 和技术信息；
- `Runner` 是执行场景的 Agent 角色；
- Main、Runner、Reviewer、Final Main 的模型会话不是独立测试记录。

### 15.2 列表字段

- 结论；
- 测试记录短 ID；
- 固定目标提交；
- 触发来源；
- 开始和结束时间；
- 耗时；
- 场景通过、失败和阻塞摘要；
- 正式报告状态；
- 清理或归档告警。

默认最新优先。使用现有数据支持结论、触发方式、时间、Run ID 和 commit 的局部筛选；不建立跨项目全局搜索。

### 15.3 独立详情

每条测试记录使用稳定 URL。列表和详情不使用窄栏主从抽屉。

#### 摘要

- 正式结论；
- 错误或阻塞原因；
- 项目和触发来源；
- base commit、target commit 和 included commits；
- 配置修订和不可变执行镜像事实（已有时）；
- 开始、结束和耗时；
- 清理、归档和推进状态。

#### 场景结果

- 场景 ID 和名称；
- passed、failed 或 blocked；
- 关键说明；
- 对应证据；
- 进入场景详情。

#### 审核

- Reviewer 审核工件；
- 审核结论；
- 发现的问题；
- 与计划和执行结果的关系；
- 不把 AI 审核显示为人工评分。

#### 正式报告

- 渲染后的正式报告；
- Markdown 原文；
- Git 来源 commit；
- 归档状态；
- 稳定地址或目标仓库文件入口。

正式报告拥有可深链接 URL，但不单独建立报告列表页。

#### 证据

按场景和类型组织：

- 截图缩略图与大图；
- 拍摄时间、来源步骤、对象哈希和完整性状态；
- trace 和日志的类型、大小、生成时间及打开入口；
- 可用、缺失、完整性失败、读取失败或外部存储不可达；
- 合成截图检测标签和警告。

证据失败不能自动等同于功能失败，但必须影响审核可信度。禁止为截图清空表单、覆盖页面状态或隐藏待验证内容。

#### 技术信息

默认折叠：

- 完整 Run ID；
- projectId；
- 配置修订；
- commit 与 digest 完整值；
- artifact 名称；
- 安全的活动和错误代码；
- Issue、场景 PR 和归档重试状态。

不展示 Secret、思维链或未经脱敏的原始命令环境。

## 16. 场景

### 16.1 页面定位

场景页是 Git 场景资产的只读目录，不是在线测试用例管理器。

### 16.2 场景列表

- ID；
- 名称；
- 描述；
- `draft / approved / deprecated`；
- 标签；
- 最近一次测试结论和时间；
- 来源文件路径；
- 最近同步 commit；
- 陈旧缓存或同步错误。

支持名称、ID、状态和标签的项目内筛选。

### 16.3 场景详情

- 完整 Markdown 内容；
- 目的；
- 前置条件；
- 步骤；
- 期望；
- 需要记录；
- Git 来源和同步状态；
- 最近执行历史；
- 相关正式报告、Issue 和待审核场景 PR。

历史使用可扫描列表，不强制使用趋势图。

### 16.4 不放什么

- 在线编辑或删除；
- 批量修改状态；
- 手工测试套件；
- 勾选场景后运行；
- 绕过项目维护模式和 Git PR 的操作。

## 17. 运行准备

### 17.1 页面目的

回答“项目现在为什么能测试，或者为什么不能测试”。这里执行检查、同步和镜像准备，不编辑配置。

### 17.2 总体结论

- 已就绪、未就绪或检查中；
- 最后检查时间；
- 全部阻塞原因；
- `重新检查`。

当前没有就绪检查历史，本版不展示历史记录。

### 17.3 仓库与同步

- 已核验 GitHub 仓库身份；
- 场景分支；
- 最近同步 commit 和时间；
- 缓存陈旧状态；
- Git 远程访问结果；
- `同步场景与报告`。

#94 必须使不可达 Git 检查在有界时间内结束，并返回脱敏、可操作的失败信息。

### 17.4 执行镜像

- Dockerfile 来源；
- 未准备、准备中、已准备或失败；
- 对应固定 commit；
- 镜像 digest；
- 最后更新时间；
- `准备或重建镜像`。

不得临时回退到服务容器执行项目任务。

### 17.5 测试环境

- 非生产环境地址；
- 环境检查结果；
- 测试账号配置状态；
- 清理能力配置状态；
- Secret 只显示状态，不显示原值。

### 17.6 共享依赖

- 模型 Provider；
- 浏览器；
- OSS；
- 受全局故障影响时链接到“系统状态”或“全局设置”。

### 17.7 状态语义

必须区分：

- 已保存；
- 已配置；
- 连通性通过；
- 完整就绪。

## 18. 项目设置

### 18.1 页面共同规则

- 顶部持续显示项目名称和仓库；
- 每组独立保存；
- Secret 与普通配置分开提交；
- 未保存修改时切换页面需要确认；
- 活动任务导致配置锁定时，显示具体测试记录；
- 修改后需要重新检查、同步或准备镜像时，给出正确入口；
- 保存成功不能显示为就绪通过。

### 18.2 基本资料

- 项目显示名称；
- 仓库稳定身份只读；
- 创建时间；
- projectId 放入次要技术信息；
- 仓库身份不可编辑的事实。

暂停和恢复放在项目上下文栏和项目列表，不藏在设置深处。

### 18.3 测试策略

- 场景分支；
- 场景维护模式；
- 固定包含标签；
- 生成语言；
- 其他已有项目级测试选择配置。

### 18.4 测试环境

- 非生产环境说明；
- 服务地址；
- 外部数据库说明；
- 清理地址和非 Secret 配置；
- 明确的非生产环境约束。

### 18.5 执行环境

- 项目执行 Dockerfile；
- 现有构建配置；
- 保存后进入“运行准备”准备镜像并验证；
- 不在设置中复制镜像构建进度。

### 18.6 自动化

- Git 轮询；
- 定时触发；
- trigger-on-commit；
- 当前启用状态；
- 项目暂停时明确自动请求不会被认领。

### 18.7 凭据

- GitHub Token；
- 测试账号；
- 测试密码；
- 清理 Token；
- 已配置/未配置和安全掩码；
- 更新、轮换和清除分别确认；
- 原值永远不返回前端。

## 19. GitHub Issue 和场景 PR

不建立独立管理页：

- 测试记录详情显示相关 Issue；
- 场景详情显示场景 PR；
- 项目概览显示待审核数量；
- 工作台把需要处理的 PR 列为事项；
- 显示 GitHub 状态、最近同步时间和外部链接；
- GitHub 继续作为 Issue/PR 事实源。

## 20. 加载、空、错误和陈旧状态

- 页面区域独立加载；
- 局部失败不遮挡其他正常区域；
- 有缓存时展示最后可信数据并标记陈旧；
- 没有缓存时显示真实空状态；
- 失败区域可单独重试；
- 全局公共依赖失败才升级为全页提示；
- 项目 A 失败不能遮挡项目 B；
- 自动刷新失败不能清空内容、抢焦点或重置滚动位置；
- 设置保存失败保留用户输入。

必须区分：

```text
加载中
没有数据
加载失败
显示陈旧缓存
权限或配置不足
```

骨架只表示加载，不能填入仿真的测试结果和数字。

## 21. 确认与危险操作

### 21.1 无需确认

- 重新加载；
- 运行就绪检查；
- 同步只读索引；
- 打开报告；
- 复制 ID；
- 修改尚未提交的表单。

### 21.2 普通确认

- 发起测试；
- 暂停或恢复项目；
- 启用项目；
- 准备或重建镜像；
- 放弃未保存修改。

确认内容显示项目、仓库、来源和具体后果，不使用只有“确定/取消”的无信息弹窗。

### 21.3 高风险确认

- 清除凭据；
- 替换关键凭据；
- 修改可能破坏历史证据地址的 OSS 配置。

只有真正难以恢复的操作才要求输入确认短语。本版没有永久删除项目和清空历史，不预设相应界面。

## 22. 时间、提交和标识

- 最近时间可以显示相对值，同时提供完整时间和时区；
- 超过一天的记录默认显示完整日期；
- commit 默认显示前 12 位，可复制完整 SHA；
- 镜像显示短 digest，可复制完整值；
- 固定提交与移动中的分支 HEAD 明确区分；
- 列表显示短测试记录 ID，详情提供完整 Run ID；
- projectId 等内部标识放在技术信息；
- 普通状态使用中文，`Run ID`、commit、digest、Dockerfile 等准确技术词保留英文。

## 23. 桌面与 Pad 范围

- 主设计宽度：1440px；
- 最低支持宽度：768 CSS px；
- 只设计桌面操作流程；
- Pad 不单独设计导航或页面，只做必要媒体查询；
- 768–1023px 可缩小页面边距、多列改双列或单列、上下文栏换行、设置侧栏折叠；
- 表格可以保留主要列并让次要信息展开或局部横向滚动；
- 主内容、页面顺序和操作流程不变；
- 低于 768px 不承诺可用；
- 200% 缩放在满足最低有效宽度的桌面环境中验收。

## 24. 可访问性

- 全部操作可使用键盘；
- 焦点始终可见；
- 弹窗正确锁定并归还焦点；
- 状态不能只靠颜色；
- 正文、弱化文字和边框满足对比度要求；
- 表格有正确表头和阅读顺序；
- 字段错误与输入关联；
- 自动更新不抢焦点；
- 动画遵循 `prefers-reduced-motion`；
- 200% 缩放不丢失内容和操作；
- 证据预览提供可读名称和必要替代文本；
- 关键操作不能只在 hover 时出现。

## 25. 路由和页面形式

重要对象必须使用真实页面和稳定 URL：

- 项目工作区；
- 项目接入向导；
- 测试记录详情；
- 场景详情；
- 正式报告；
- 账号设置；
- 设置分组。

弹窗只用于短确认。不得使用右侧抽屉承载完整测试记录、完整场景、长篇报告或复杂设置。

建议的逻辑路由为：

```text
/login
/workspace
/projects
/projects/new
/system
/settings/:section
/account
/projects/:projectId/overview
/projects/:projectId/test
/projects/:projectId/runs
/projects/:projectId/runs/:runId/:tab?
/projects/:projectId/scenarios
/projects/:projectId/scenarios/:scenarioId
/projects/:projectId/readiness
/projects/:projectId/settings/:section
```

具体路由库可由实现计划决定，但刷新、深链接和项目归属不能依赖进程内临时选择。
