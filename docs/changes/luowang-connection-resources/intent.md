# 命名连接资源 Intent

- 日期：2026-10-05
- 状态：已确认

## 问题

- GitHub Token 目前直接绑定单个项目，无法命名、识别或安全复用于另一个项目。
- 执行服务器没有独立配置入口，也不能表达项目使用哪台服务器。
- 新项目接入时必须重复输入已有 Token，容易造成凭据重复、命名混乱和轮换遗漏。

## 期望结果

- GitHub Token 作为可命名的加密连接资源管理；项目只绑定资源，不复制或回显明文。
- 新项目只选择已有 Token；需要新增时跳转到统一的 GitHub 设置，避免在接入流程重复实现资源编辑。
- 可配置命名执行服务器，记录主机、端口、用户和密码或 SSH 私钥；项目可绑定服务器。
- 未绑定执行服务器的项目明确使用罗网所在服务器。

## 约束

- Token、密码、私钥和私钥口令只进入 Secret Store，接口和日志不得返回明文。
- 已有项目专属 Token 保持可用，不因本次升级失效。
- 本批次只建立服务器配置、Secret 和项目绑定；远程执行协议及调度不在本次实现范围内。

## 非目标

- 不在本批次实现远程 SSH 命令、远程 Docker 生命周期或文件同步。
- 不把测试账号、模型 API Key 或 OSS 凭据合并进 GitHub Token 资源。
