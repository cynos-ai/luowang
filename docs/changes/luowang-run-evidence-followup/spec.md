# Run 证据与执行记录修复 Spec

## 证据

- 复用现有 command 证据 ID、Run/target 绑定、哈希和 Reviewer 读取通道。MCP 记录由 Harness 从真实工具事件捕获，不接受 Runner 自填正文作为原始证据。
- 记录受控 Cookie 读取/恢复与请求的时序、成功或错误、脱敏参数和输出。以本 Run 内不可复用的凭据标识保留相等关系；不能因简单移除 Cookie 而声称请求使用了原 Session。捕获、内容解析或请求关联不充分时保留限制，不能凭工具调用成功判断业务通过。
- 固定 Playwright 1.63.0-alpha-2026-08-05 的网络详情原实现使用会省略 Cookie 的 `headers()`。构建时针对固定实现应用 `allHeaders()` 修补，同时覆盖完整详情及 request-headers 分项，不升级依赖或新增工具。版本或源码形状不匹配立即失败；重复应用幂等，runtime 复用构建产物。真实本地浏览器与合成服务核对实际请求，并分别验证两种详情读取。
- 自定义非图片文件不得绕过脱敏直接上传。未纳入受控来源的文本拒绝上传，保持本地历史不变；不因文件名像命令证据就取得受控身份。截图仍沿用现有图片通道及测试账号不得入图的规则。
- 证据捕获失败、篡改和真实读取失败保持可见，不能伪报存储成功。未知工具、任意路径、其他 Run 不获得读取资格。

## 进度与报告

- 正式场景的开始在其实际操作之前，完成在操作之后；初始化侦察仍不使用正式场景进度。
- 命令证据保留实际执行时的场景归属和时间；辅助操作必须如实标明，不能以事后补进度把它改为场景内操作。Harness 不用命令或测试名称推断业务归属。
- MCP 和进度记录使用本 Run 内的 `operation-N.json`，复用 command 类型、完整性映射和读取工具；不是新的证据类别或长期事实源。控制台活动同步显示实际开始的命令/浏览器操作及当前场景或辅助归属。模型给错业务归属仍须 Reviewer 结合记录审核，不能宣称代码自动理解了命令含义。
- Runner 和 Reviewer 明确核对事件/操作顺序；进度问题不能把已有充分证据支持的产品成功改为产品失败。
- 不复述公开样例口令或真实凭据值。无泄漏声明必须限定扫描对象、方法和结果；无扫描事实时不得声明已扫描。保留源码与历史记录，不引入业务关键词决定结果的门禁。

## 验收

- AC-FOLLOWUP-01：受控重放结果进入既有 Reviewer 通道，保持 Run 隔离和完整性，原始凭据不持久化或上传。
- AC-FOLLOWUP-02：自定义文本、伪造命令文件不能绕过上传边界，已获准证据保留实际脱敏字节。
- AC-FOLLOWUP-03：进度与真实操作时序可核对，辅助/未声明操作不能被伪装为已实时执行的场景。
- AC-FOLLOWUP-04：角色指令明确最小披露和有范围的检查结论，受控凭据保护单独回归。
- AC-FOLLOWUP-05：quality 容器工程检查通过，README 准确区分工程通过、真实样本与人工评分；真实复验未完成时不关闭对应效果验收。
