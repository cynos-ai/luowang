# 同一操作者管理多个 Git 项目 Spec

- 版本：v0.6.1，按负责人指定编号；本版包含多项目功能，发布说明须明确其数据和接口变化，不能仅因补丁版本号宣称向后兼容。
- 状态：实现规格；2026-09-23 编写，2026-09-24 加入项目执行镜像；已有分阶段实现，完整功能尚未贯通。
- 输入：[intent](intent.md)；前置：[代码深读 v0.6.0](../luowang-code-understanding/spec.md)。

## 1. 产品边界

一个罗网部署、一个现有操作者登录，可以管理多个 GitHub 项目。每个项目对应一个仓库、一条场景测试分支和一个非生产测试环境；不新增用户注册、组织、团队权限、多环境矩阵或单项目多仓库。

操作者身份仍是唯一管理员。账号页提供可编辑的显示名称、修改密码和退出登录；旧实例升级时显示名称默认为“管理员”，名称仅用于界面展示，不作为登录名、项目所有者或授权依据。初始密码继续只从 `LUOWANG_ADMIN_PASSWORD` 设置，已有密码哈希不被环境变量覆盖；改密码沿用撤销现有会话的规则。不新增邮箱、注册、邀请、用户列表或角色权限。所有项目属于这个部署，不出现可切换的“当前用户”后台状态。

本 Spec 覆盖默认布局、PROJECT.md、MVP 和 production-closure 的单仓库配置、索引、调度及 Run 归属规则。每个项目内部继续执行固定提交、场景状态、角色隔离、场景 patch、证据、清理、归档和模型语义判断的既有规格。v0.6.0 的深读方法保持共用，理解事实不能跨项目混用。

全局同时最多一个执行中的 Run。归档、索引和依赖检查按项目隔离，不能因一个项目的可恢复失败让其他项目长期失去执行机会。仍为可信代码、单操作者系统，不宣称提供恶意租户隔离。

本版的项目隔离包含归属、访问、工作目录与项目专属执行镜像。罗网服务镜像保留调度、Agent、Git、浏览器和归档能力；目标项目的受控构建/测试命令在该项目镜像的执行容器中运行，不要求服务镜像预装所有语言工具链。项目镜像可复用，Run 不重新构建一次性镜像；每次执行仍使用独立容器与工作目录，结束后清理。镜像构建和包脚本会运行目标仓库代码，本版只接入操作者信任的仓库，不宣称为恶意代码安全沙箱。目标项目的非生产应用仍由操作者提供，罗网不自动部署它。

## 2. 项目生命周期

### 2.1 身份与创建

- 项目有服务端生成的稳定不透明 projectId、显示名称、规范化仓库身份、配置修订号、创建/更新时间和 `active | paused` 状态。
- projectId 不能从显示名称、URL 文本或前端当前选择推导。身份以服务端绑定的 GitHub 仓库 ID 及规范化 owner/name 为准；所有 URL/别名须经现有可信 GitHub 规则校验。
- 同一个 GitHub 仓库不允许重复接入，即使 URL 大小写、尾部 `.git` 或别名不同。仓库身份创建后不可编辑；连接不同仓库需创建新项目。
- 创建时必须完成仓库身份校验；私有仓库需同时提供可验证身份的项目凭据，校验失败不创建未绑定项目。新建项目默认 paused，测试环境等其余配置缺失可保存并显示未就绪原因。就绪且由用户恢复后才参与自动调度；不因保存配置自动开始测试。
- 仓库改名等身份变化必须复核稳定 GitHub ID；不可确认时停止该项目的新测试，不静默连接新仓库。

### 2.2 暂停与恢复

暂停阻止新的手工测试请求和自动触发，也不认领已有 queued 请求；已 queued 请求保留。暂停与认领在同一协调边界内判断，暂停不能悄悄漏掉已经认领的任务。

已运行或已进入准备流程的任务按其固定上下文继续完成及清理；暂停不隐含取消、重跑或改判。已产生的待归档任务继续重试，索引、历史读取和凭据修复仍可进行。界面明确“已暂停新测试，现有任务仍在处理”。

恢复后重新做就绪检查，按原队列顺序处理保留请求，再接受后续自动触发。v0.6.1 不提供项目永久删除、历史删除或无提示的数据重置。

## 3. 配置与凭据归属

| 范围 | 内容 |
| --- | --- |
| 部署级 | 管理员认证、主密钥、Provider 与三组 Agent 模型配置、浏览器配置、OSS 连接、存储根目录及保留策略 |
| 项目级 | 仓库身份、场景分支、场景维护模式/标签、生成语言、测试环境说明与 URL、外部数据库说明、清理配置、轮询/定时触发配置及执行镜像构建配置 |
| 部署级 Secret | Provider API Key、OSS 访问凭据 |
| 项目级 Secret | GitHub Token、测试账号/密码、测试数据清理 Token |

创建项目时生成语言可从部署默认值复制，此后独立修改。本版不提供项目级模型和 OSS 覆盖配置，避免隐式继承规则。

### 3.1 Secret Store

沿用统一加密 Secret Store，在存储键与 AES-GCM AAD 中共同绑定 scope、projectId（部署级使用固定 scope）和 Secret 名称。缺少本项目 Secret 必须明确未配置，不回退到其他项目或部署级 Git Token。API 只返回配置状态与掩码，模型只获得本任务原本允许的环境信息。

项目服务只注入已绑定 projectId 的凭据访问器；调用方不能通过任意参数切换项目。跨项目复制密文、替换 scope 或使用其他项目 Secret 引用时解密/访问失败。日志、配置导出、连通性结果和错误消息同样限定归属并脱敏。

### 3.2 任务与配置修改

入队时固定 projectId、仓库身份、项目配置修订和非 Secret 配置快照；目标提交仍按现有准备/解析步骤固定，不在入队时假造已解析 target。

存在 queued、准备中、运行中或 waiting_archive 请求时，不允许改变该项目的场景分支、测试环境、测试账号、清理目标、执行镜像构建配置或维护策略等任务语义配置，返回冲突及待处理任务摘要。项目名称、暂停状态、轮询/定时配置可修改，但不改写已有请求。跨环境变更须在本项目任务排空后进行。

GitHub/OSS 访问凭据允许原位轮换，以修复认证失败；后续副作用使用最新的同 scope 凭据，只能操作任务已经固定的仓库或对象存储目的地，失败不能改投其他位置。测试账号和清理凭据在本项目活动任务完成前不得替换或删除，避免执行和收尾使用不同身份。

部署模型/浏览器非 Secret 配置在全局没有准备中或运行中任务时更新，下一个被认领请求固定实际生效的部署配置并记录。Provider 凭据不在 Session 中途切换。OSS 的历史证据必须保留原目的地；存在引用时禁止原位更改 endpoint/bucket/prefix/publicBaseUrl 等会使地址失效的配置，本版不实现对象存储迁移。

## 4. 数据和服务隔离

### 4.1 数据身份

新增项目实体，在项目配置、Secret、索引状态/错误、场景、Run（含 interrupted）、队列、推进位置、调度状态、连通性结果和归档工作上建立明确项目归属。Run 子记录可以通过有约束的父记录继承 projectId，但查询和副作用不能绕过父记录验证。

| 数据 | 唯一性或关联规则 |
| --- | --- |
| 场景索引 | `(projectId, scenarioId)` 与 `(projectId, path)`；取消全局场景 ID 唯一约束 |
| 目标仓库报告索引 | `(projectId, runId)` 与 `(projectId, path)`；不同仓库可含相同的历史报告 Run ID，读取必须带项目归属 |
| 索引状态与错误 | 按项目及分支/路径定位，错误不得覆盖其他项目缓存 |
| Run/请求 | 保留全局唯一 Run ID/请求 ID，同时强制关联 projectId |
| 推进/调度状态 | 每项目各自记录 lastCompletedTarget、cron 去重键、轮询时间及失败状态 |
| Issue/场景 PR/归档重试 | 由 Run 绑定项目和仓库，幂等判断包含仓库身份 |
| 深读与证据 | Run → projectId → 固定提交；查询、网关和导出逐级校验归属 |

保留单 SQLite 及现有服务职责，不为每项目复制一套服务器。Repository Service、Indexer、Orchestrator、Archiver 等获得显式绑定的项目上下文；禁止使用进程级“当前选中项目”驱动后台行为。

### 4.2 文件与对象存储

新项目的 clone、准备合并 internal refs、Run 工作目录、浏览器 profile、下载/临时目录及清理登记均按稳定 projectId/Run 隔离。配置中不允许用户任意指定跨项目本机路径，拼接后检查目标仍在受控存储根内。

新 OSS 对象使用部署前缀下的 `projects/<projectId>/runs/<runId>/...`。已存在证据保留原地址和哈希，通过迁移后的 Run 所有者核对，不能重写历史报告或对象 URL。不同项目即使使用相同场景 ID、文件名和相对报告路径，也不能覆盖证据或错误获取签名 URL。

目标仓库内仍使用 `docs/scenario-testing/scenarios/**` 和 `docs/scenario-testing/reports/<run-id>/**`，不把罗网内部 projectId 变成目标项目新的目录层级。深读资源可共享，回执、计划、场景快照和模型上下文不可共享。

### 4.3 项目执行镜像

- 每项目单独配置受控的构建说明。默认可选罗网维护的基础执行镜像；需要特定语言和依赖时，由操作者选择该仓库中明确的 Dockerfile 路径。路径必须是固定提交内的普通文件，不接受绝对路径、越界路径或来自其他仓库的构建上下文。基础镜像能力和项目镜像实际可用命令应在就绪检查中显示，不把“镜像存在”当成依赖齐备。
- 接入时对当前场景分支的固定提交准备项目镜像。后续目标提交变化时，在 Run 执行命令前为该固定提交准备或复用镜像；可以使用 Docker 层缓存，但不能因为只比较文件名或时间戳而把旧代码、旧依赖用于新提交。镜像以不可变 digest 和构建输入提交记录，已认领 Run 固定该 digest；后台重建或页面切换不能更换它。相同输入可以复用，失败只能阻塞该项目的执行并显示脱敏诊断，不应占住其他项目。
- Run 从已准备的项目镜像启动执行容器，项目仓库及本 Run 的工作场景副本在容器内可见；容器内实际读取的代码必须对应记录的 `target_commit` 与本 Run 场景 patch。不能仅因本地 clone 目录名称正确就认为容器内容正确。命令执行仍经过现有允许列表、参数限制、超时、输出大小限制和证据脱敏；不回退到罗网服务容器执行目标项目命令。
- 执行容器仅获得该 Run 必需的工作目录和最小环境变量，不挂载其他项目目录、罗网数据库、主密钥或 Docker socket。需要测试账号或清理凭据的操作继续通过现有受控工具处理，不把整份 Secret Store 注入项目镜像。容器退出、超时、取消和重启恢复要清理本 Run 容器；不能把前一次 Run 留下的可变文件或浏览器状态交给下一次 Run。
- 镜像构建和容器生命周期由受控执行服务调用 Docker Engine；Web 请求、Agent 工具及项目执行容器均不能直接访问 Docker API。Docker Engine 不可用是部署级故障，应统一显示；某项目镜像构建失败是项目级故障。部署说明必须列出 Engine、存储容量和镜像清理要求，不能默默回退到宿主机命令。
- 项目配置和就绪页分别显示构建中、就绪、过期及失败状态、对应提交/digest 和重建入口。项目没有适用镜像、构建失败或镜像 digest 不匹配时不执行受控命令，不因浏览器或模型仍可用而报告完整通过。镜像构建本身会执行可信仓库代码；本版不承诺隔离恶意仓库，也不自动部署被测应用。

### 4.4 受控非生产 HTTP 验证

- Runner 可对本任务固定的项目 `baseUrl` 发出 GET/POST/DELETE，目标只能是同源绝对路径，不接受自选域名、查询、任意请求头或自动跨域重定向。每个 Runner Session 的命名 HTTP 客户端独立保存 Cookie，不与浏览器、其他客户端、其他 Run 或项目共用；仅返回 Cookie 名称，不返回值。请求体限于有界的扁平 JSON，口令使用由服务端替换的预置/本 Run 合成/错误/短口令占位符，不能在工具参数或证据里提交明文。
- 清理验证另走本项目配置的固定清理地址；普通探针只允许当前 Run ID 或固定非法 ID，部署级 Token 由服务端注入，模型不能选择、读取或输出。带正确 Token 的普通 DELETE 只允许当前 Run，场景自身要求验证清理时可执行；Harness 在最终 Main 后仍做独立收尾与余量核验。普通探针不得读取或删除其他 Run。
- 对应用与清理端点同源、兼容 `POST /api/auth/register` 的非生产目标，可在场景内调用一次性跨 Run 清理对照工具。工具自行随机生成另一个合法 Run ID 和合成账号；模型不能指定对照 ID、账号、地址或凭据。工具从真实应用注册对照账号，分别读取当前 Run 和该对照的清理余量，只删除当前 Run 后复读两者，并在同一次调用的 `finally` 中删除对照、独立确认余量为零。仅在当前 Run 和对照清理前各有账号、当前 Run 清理后为零、对照余量不变且对照最终清净时，结果才可标记通过；任一响应、范围、证据保存或清理失败均不得判通过，失败时保留对照 ID 供受控人工清理。此工具不接受任意历史 Run ID，不能证明预置账号仍可登录，后者仍须独立观察。
- HTTP 响应和必要状态由 Harness 限时、限量、脱敏后保存为本 Run 的受控操作证据，Reviewer 按证据 ID 独立读取；证据保存失败不能当作已验证。受控 HTTP 仅证明接口行为，不代替页面文本、原生校验或浏览器 Cookie 属性的 Playwright 观察。缺少适用观察时场景继续 blocked，不放宽既有期望。

## 5. 队列、后台任务和恢复

- 每项目严格处理最早未完成的请求；同项目 waiting_archive 阻止后续测试推进，但不占用全局模型执行名额。
- 跨项目按轮转选择具备执行条件的队首请求，持久记录最近调度项目；没有其他可运行项目时可以继续当前项目。自动请求只在同项目、同配置修订及相同请求语义内合并。
- 全局认领、项目暂停检查和执行租约保持原子性；恢复后不能出现两个执行者、重复准备 merge 或重复发布。
- 每个项目的索引、轮询和归档失败分别捕获，外部调用有超时和有界重试。对故障项目退避并显示错误；调度仍能继续处理其他项目，不能把同步异常冒充全局队列为空。
- 每个任务从持久记录恢复项目、配置和 fixed target。prepared/resolved internal ref 及发布前远端历史校验沿用原规则，不从当前页面或新配置重算目标。
- 运行中进程中断按既有 interrupted 规则处理，不自动声称执行或清理成功；排队与待归档恢复不重放已完成的模型 Session。
- 单项目缺 Secret、依赖失败、归档失败或历史断裂只影响本项目；主密钥不可用、SQLite 故障、全局 Provider/OSS 故障按实际公共影响报告，不伪装为项目级故障隔离成功。

## 6. API 与控制台

所有业务 API 都在认证后处理。新增 `/api/projects` 的列表/创建入口，以及 `/api/projects/:projectId` 的详情/受限更新和暂停/恢复操作。既有项目业务路由迁至 `/api/projects/:projectId/...`，部署配置与认证保留独立入口。

每条场景、Run、证据、Issue/PR、队列重试、连接检查、配置导出或清理相关请求，服务端都校验 URL 项目与数据所有者一致；不匹配按不存在处理。请求体如包含另一 projectId，拒绝冲突，不信任其覆盖 URL 上的归属。旧无项目业务接口明确不支持，不隐式选择第一个项目。

控制台登录后显示项目列表，首次空列表提供创建入口；项目页 URL 携带 projectId，刷新和深链接不会串项目。切换项目时缓存键包含 projectId，并取消或忽略上一项目的迟到响应。所有写操作提交明确的 projectId；二次确认或异步回调仍绑定操作开始时的项目。

导航将“账号”“部署设置”和“项目”分开。部署设置显示 Provider/模型、浏览器、OSS、存储和各项连通性；项目设置只显示当前项目的仓库、非生产环境、测试账号、清理和触发规则。项目配置页始终显示项目名称与仓库身份，避免在另一项目上误保存。YAML 导入导出可保留为高级入口，但不能成为创建项目或修复缺项的必经步骤；导出不得包含明文 Secret。

首次登录但没有项目时展示接入入口和部署级就绪状态。新增项目按“连接并核验 GitHub 仓库 → 填写非生产环境与项目凭据 → 选择并准备项目执行镜像 → 检查依赖和清理条件 → 明确启用”的步骤进行；新项目默认 paused，每一步可保存和返回，不强迫一次填完。仓库身份验证失败时按 2.1 节不创建项目，其余未完成配置保存在已绑定仓库的 paused 项目中。每项检查显示通过、未配置、失败或待重检及可操作原因；保存与连通性检查分别呈现，不能把字段已保存或镜像已构建显示成所有依赖均已通过。只有就绪检查通过且管理员主动恢复项目后，才接受新的 Run 或自动触发。

项目概览持续显示就绪清单、当前状态、最近检查时间、同步提交、最近 Run 和阻塞原因。凭据字段只显示已配置状态及掩码；替换/清除前说明对活动任务的限制，配置冲突按 3.2 节阻止并指出待处理任务。暂停入口解释运行中和待归档工作仍会继续；恢复时重新检查，不因编辑配置自动启用。首次向导与日后项目设置使用同一组服务端校验和就绪判定，避免出现两套规则。

项目页呈现该项目的场景、Run、队列、归档、依赖健康和最近同步提交，失败缓存标记陈旧。提供全局正在执行任务的项目名称与链接，其他项目排队时能看出等待原因。显示名称只用于展示，不能决定数据归属。

## 7. 已有数据升级

不维持旧 API、旧配置结构的双轨兼容；保留已有数据是升级要求，不以用户“不考虑兼容性”为删除历史授权。

升级在停止调度、停止服务并备份 SQLite、受控数据目录和必要加密配置后离线执行。备份留在受控位置，不写入 Git；回退需恢复配套数据库与目录，不在已迁移数据库上运行旧程序。

- 空实例升级后保持零项目，不创建虚假默认仓库。
- 有唯一有效旧仓库的实例，创建一个 paused 项目，显式归属全部旧 Run、请求、进度和索引；旧项目配置及 Secret 一次性迁入对应 scope，部署凭据保留部署 scope。
- 数据存在但仓库身份不明、历史混入多个仓库或 Secret 无法解密时，迁移停止并给出脱敏原因；不凭“当前配置”猜测历史归属。
- SQL 迁移与 Secret 重加密在可回滚事务内完成，失败不留下半套归属。旧 Run ID、结果、提交、时间、报告内容和证据 URL 不变。
- 旧工件目录暂以受控历史路径与唯一项目关联，新的写入使用项目目录；不批量搬动或重写旧工件。索引可重新构建，但原正式 Git 事实不变。
- queued 请求保留在 paused 项目；running 请求依原恢复规则标 interrupted；待归档工作保留，但迁移后须明确恢复项目才能启动首次后台副作用。
- 迁移成功后以单项目回归核对归属、解密、历史读取、恢复与归档幂等，再接入第二个项目。

迁移脚本需要幂等标记、前后数量及关键内容哈希核对。无法可靠归属的数据必须先处理，不允许通过忽略错误来完成升级。

## 8. 验收条件

| ID | 验收要求 |
| --- | --- |

| AC-MP-07 | 暂停/恢复与认领竞争、配置冲突和凭据轮换规则可复现验证 |
