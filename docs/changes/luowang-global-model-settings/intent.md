# 全局设置模型页易用性修正 Intent

## 当前问题

v0.7.1 上线后，操作者在真实控制台配置模型时遇到三个问题：

1. 选择或填写 Provider 后，`Provider Base URL` 仍为空，需要自己查并抄写默认地址；Pi 目录里已有该 Provider 的默认地址，却没有被利用。
2. 模型页看不到 Provider API Key 的填写入口；Key 在“全局凭据”分组，首次配置模型时必须来回切换页面。
3. 页面存在与操作无关的解释性文案：分组标题下的说明段、字段下方重复字段名含义的提示，以及目录状态里的补充说明。

已有基础：`GET /api/provider/providers` 与 `GET /api/provider/models` 由 Pi `ModelRuntime` 提供，包含 Provider 默认 `baseUrl` 与模型能力元数据；多项目服务已在 #112 补齐这两个路由。

## 期望结果

- 选择 Pi 已知 Provider 时自动带出该 Provider 的默认 Base URL，仍允许手工改写或留空。
- 在模型与角色分组内直接填写并保存 Provider API Key；全局凭据分组继续保留轮换和清除能力。
- 移除与操作无关的解释性文案，只保留真实状态、能力警示和错误信息。

## 影响

主要影响全局设置页面、`ProviderInfo` 目录响应和浏览器 E2E；不改变 Provider 解析、连接检查、Run 调度、归档或密钥存储语义。

## 约束

- Base URL 自动填充只使用 Pi 目录公开的默认地址；不猜测、不伪造未知 Provider 的地址。
- API Key 仍只通过现有 Secret Store 接口写入，不回显、不写入日志或普通配置；两个页面共享同一 Secret。
- 保存配置不等于连接检查通过，仍需单独的连接检查流程。
- 未知 Provider、目录加载失败和目录为空时，输入不被静默清空或覆盖。

## 非目标

- 不建立 Provider 凭据库、每角色独立 Provider 或模型目录编辑器。
- 不新增自动远程拉取账号可用模型的能力；目录仍是已知模型元数据。
- 不重做其他设置分组的内容或 v0.7 视觉语言。

## 待确认问题

无。
