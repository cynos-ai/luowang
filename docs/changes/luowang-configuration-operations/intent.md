# 罗网配置操作优化 Intent

## 当前问题

管理员从设置页配置罗网时，现有交互仍有四类歧义：

1. GitHub 的仓库、分支、Pull Request、Issue 能力以四个独立测试按钮呈现，用户难以判断是否需要逐个操作；能够从 classic PAT scope 安全判断的写权限仍显示为 `unknown`。
2. “自动触发”没有明确说明轮询只负责发现新提交，秒级输入也不符合日常配置习惯；虽然 commit trigger 默认关闭，但页面不够直观。
3. 连通性总览仍要求逐项点击，缺少一次测试全部已保存配置并集中解释问题的入口。
4. 配置无法在部署间备份和迁移，只能手工重复填写。

## 期望结果

- GitHub 只提供一个“保存并测试 GitHub”动作，在同一结果块展示四项子能力及原因。
- 自动测试明确默认关闭，新提交检查间隔用分钟表达，并说明它不是固定周期执行测试。
- 连通性总览提供唯一“测试全部”动作，逐项展示通过、失败、未配置、未启用及具体原因。
- 支持普通配置的 YAML 导出和原子导入。

## 影响

设置页、Connectivity API、GitHub 权限判断、自动触发默认值与配置迁移操作。

## 约束

- 所有检查只使用已保存配置。
- GitHub 检查不得创建测试 PR、Issue 或 force push。
- YAML 不导出、不接受或覆盖任何 Secret；Secret 继续只存在于 Secret Store。
- 配置导入必须严格校验、原子写入，并遵守 active Run 期间仓库身份不可变规则。
- 旧数据库的既有轮询值保持兼容。

## 非目标

- 不把 YAML 作为新的运行时事实源。
- 不支持 Secret 明文导入导出或 SecretRef 编排。
- 不增加后台定时连通性检测。
