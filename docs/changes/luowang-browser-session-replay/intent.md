# 受控 Cookie 会话重放能力

## 当前问题

`AUTH-LOGIN-001` 要求以“退出前原 Session 仍被拒绝”证明退出确实撤销了服务端会话，并要求删除账号后旧 Cookie 与原凭据都不可用。产品当前的隔离浏览器没有 Cookie 读取/恢复工具，`browser_network_request` 只能查看历史请求、不能重放；Runner 也不允许任意 JS 或内联 HTTP。因此该期望无法被真实观察，只能 blocked。

合并后新轮的零模型预检已验证：MCP 真启动、状态目录、tmpfs、导航与截图全部通过，但两个非生产沙箱的工具清单都缺少 `browser_cookie_get`/`browser_cookie_set`，预检按放行条件失败，业务 Run 未创建（请求 0/300）。

## 期望结果

在既有的 headless、isolated、快照式浏览器边界内，为 Runner 增加**仅 Cookie 的读取与恢复**能力：能读取当前 Cookie 值及属性，能在退出后用原值恢复一次请求以证明原 Session 已被拒绝。能力由产品固定提供，不由评测驱动临时覆盖。

## 影响

- Runner 的 MCP 工具清单新增三项只读/恢复操作；Main、Reviewer 和最终汇总不获得该能力。
- 预检与连接检查会校验该表面真实存在，且未获授权的工具仍然不可见。
- 日常实例、历史 Run、阶段 thinking、清理资源域和工件职责不变。

## 约束

- 只允许 Cookie 读取与恢复；禁止任意脚本执行、状态文件导出/导入、local/session storage 变更、Cookie 删除/清空以及通用 HTTP 能力。
- 仍只能在非生产沙箱、Run 前缀合成账号上使用；不得读写生产数据或共享账号。
- 完整 Cookie 值只进入当次模型上下文用于重放，不写入报告、证据文件或 Git。
- Playwright MCP 版本继续固定；能力通过既有 `--caps` 开关启用，不新增容器权限。

## 明确不做

- 不新增 HTTP 代理、SQL、Docker socket、任意路径或删除权限。
- 不修改场景正文、历史报告或首轮失败记录。
- 不承诺发布、部署或全站验收。

## 待确认问题

- 无。负责人已批准仅补充隔离浏览器的 Cookie 读取/恢复能力，并继续禁止任意 JS 与状态文件导出。
