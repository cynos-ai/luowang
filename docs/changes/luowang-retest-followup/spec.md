# 复测问题收敛 Spec

- MCP以当前Node可执行文件启动从Harness自身依赖位置解析的已安装CLI；不从目标仓库或证据目录解析依赖，不使用npx在线下载回退。证据目录仍为cwd，headless/isolated与禁用任意代码工具边界保持。
- 单份权威交接不限制所属Session重写同一工件。Main发现判断变化或patch失败后必须纠正计划中的失实描述；Reviewer结合实际patch状态审核维护声明，不另起Session或增加语义正则。
- 原样复用工具返回的证据地址；没有地址时只引用已知证据ID，不构造URL。程序地址校验是否需要增加，先检查已有owner和边界，再实施，不用新的语义门禁替代审核。
- 仅对本Run获准使用且已启用MCP的范围，Reviewer可只读本Run已上传的固定版本MCP自动命名快照（page-时间戳.yml）和控制台记录（console-时间戳.log）；不开放任意文本、路径或其他Run。使用既有上传引用，不另建事实源。浏览器文本由Harness在Runner结束后统一脱敏上传，Runner工具只告知延后保存、不伪报成功；存储接收已固定的脱敏字节而非重新读取仍可能变化的文件。读取时校验上传hash、UTF-8和大小，再次脱敏后有限输出；截断明示。文件名只用于格式准入，不据此断言业务通过。
- 审核列表明确证据类型和读取工具。错误ID/工具类型拒绝不读取正文，不计作真实读取失败，也不满足原始证据读取顺序。已知证据的存储读取、内容或完整性失败仍阻塞；不清除既有失败以追求通过。
- 浏览器记录须在计划及存在的patch之后读取。是否需要某份快照由Reviewer判断，不新增每步截图或全部日志必读门禁；初始状态截图不代替反向操作后的事实，截图裁切不等同控件被遮挡。
- 零执行场景理由只在execution_scenarios为空时适用；无场景维护不等于无执行。报告只写本批适用结论，如实区分模型审核与人工复核，按截图实际覆盖描述观察，不用操作成功反证截图完整。保留实际功能结果与证据限制，不增加语义正则、状态字段、角色或强制逐图证明。
- 验收区分：工程回归、断网MCP真实启动/截图、定向模型复测、实际部署联合验收。基础测试使用Coding Plan，最终候选使用原生DeepSeek；本次只重放Reviewer与最终Main，不改正式模型/思考配置、不重跑网站、不改旧Run。前一层通过不代表后一层通过。只本地提交，不push/merge/release。
